# SOLA 7.11.0: find and rotate a key everywhere Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An admin can see every place an API key is stored (by last four characters, never the key), and replace one key everywhere in a single command, with no change to the data model.

**Architecture:** A read-only `key_inventory` class walks every store a key can live in (Providers and keys rows, the five pasted-key settings, the voice provider rows, the legacy `apikey` mirror, per-course keys) and groups identical keys by a keyed fingerprint. A `key_rotation` class plans and applies a replacement across all of them, editing the key table as text lines (as the 7.9.0 upgrade does) and concealing every new value with `secrets::conceal()`. A CLI wraps it, a Reports > Status check reports duplicates, and one small bug in `course_settings.php` is fixed.

**Tech Stack:** PHP 8.1+, Moodle 4.5+ (core `\core\encryption`, `\core\check\check`, `cli_get_params`), PHPUnit (`advanced_testcase`).

**Spec:** `docs/superpowers/specs/2026-10-18-settings-simplification-design.md`, section 5 and ruling 10. The code map this plan rests on is in the build ledger; the facts used are restated below.

## Global Constraints

- Moodle 4.5+, PHP 8.1+, component `local_ai_course_assistant`. **No schema change, no new config name, no new capability, no `db/upgrade.php` step.** Only the version bump.
- **No key, ciphertext or fragment of one beyond the last four characters of a key of 12 or more characters (`provider_keys::last4()`) may appear in any output, log, exception message, audit row, test failure message or status page.** The fingerprint is `substr(hash_hmac('sha256', 'keyfp|' . $plain, get_site_identifier()), 0, 12)` and is safe to show.
- Keys are read only with `secrets::get()` / `secrets::reveal()` and written only with `secrets::conceal()`. `secrets_test` fails on a `get_config()` of a secret name outside the helper unless the line is marked `Raw on purpose`; `provider_keys_no_raw_read_test` allows only `classes/provider_keys.php` to `get_config('comparison_providers')`.
- The key table (`comparison_providers`) is edited as TEXT LINES: every line that holds another key stays byte-identical (pinned in `provider_keys_upgrade_test`). Rows are `provider|key|models|temperature|baseurl`; the first column is the provider id; a duplicate provider is allowed.
- `provider_keys::sync_after_writes()` (or `sync_default_key()`) must run after any write that can change the key chat mirrors into `apikey`.
- PHPDoc with `@param`/`@return` and PLAIN `array` types on every method (a generic `array<...>` @param fails `phpdoc_param_consistency_test`). No em dashes; US English; contractions where natural. A commit that adds a `get_string()` call carries its `lang/en` key and its `KNOWN_UNTRANSLATED` entry (in `tests/lang_completeness_test.php`) in the SAME commit.

After a `version.php` bump run `php admin/tool/phpunit/cli/init.php` first. `scripts/prove_test.py` (needs `SOLA_REPO` set to this worktree) proves a guard can fail; never mutate the tracked tree and restore it.

- The audit writer used elsewhere (for example `provider_key_displaced`): find it in `provider_keys.php` around line 531 and use the same call.

## Review Focus

1. No key can reach any output: a failing test message, an exception, the audit row, `--json`, the status page. (Tasks 1 to 3 plant sentinel keys and assert absence everywhere.)
2. A rotation that fails halfway must not leave two different keys for one provider: all writes happen inside one delegated transaction, and a failure rolls everything back. (Task 2.)
3. An ambiguous old key (two different keys sharing the last four) is refused, never guessed. (Task 2.)
4. A new key that belongs to another vendor is refused before anything is written. (Task 2.)
5. The key table's other lines stay byte-identical, including a legacy plain-text key line and a line with a base URL. (Task 1.)
6. After rotating the default provider's key, chat uses the new key: the `apikey` mirror is in step. (Task 2.)

- Produces:

  - `key_inventory::places(): array`, a list of arrays `['kind' => 'row'|'pasted'|'voice'|'mirror'|'course', 'ref' => string, 'provider' => string, 'courseid' => int, 'course' => string, 'last4' => string, 'fingerprint' => string, 'baseurl' => string]`. `ref` is the provider id for a row, the setting name for pasted and mirror, the voice row's provider for voice, the course short name for a course. `courseid` is 0 unless kind is course. The caller conceals; this method never sees a plain new key.
