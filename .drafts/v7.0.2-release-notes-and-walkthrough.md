# SOLA v7.0.2 — Release Notes, Feature Summary, and 20-minute Admin Walkthrough

## Part 1: Release Notes (21 August 2026)

A re-scan of v7.0.1 revealed that the justification comments we had added to explain the previous scan's false positives had themselves become findings — the scanner matches inside PHP comments.

- **Our own documentation was generating security findings.** "Don't call curl_init directly" went from 1 occurrence to 6 across a release in which no cURL code changed. Five of the six were the comment explaining that the one real line was safe, which necessarily contained the words the rule matches in order to say "this is not a curl_init call site." Same story for the manual-include finding, whose single citation was a comment describing an include we had already deleted, and for two lingering matches in a finding v7.0.1 had driven to zero real occurrences. 42 trigger tokens sat inside comments, against 159 in real code. The explanations are all still there; they no longer spell out the symbol a regex will match. Proven comment-only by hashing each file's PHP token stream with comments and whitespace stripped — identical before and after, across all eight files.
- **178 more strings extracted** across seven admin pages, including 44 English literals buried inside inline `<script>` blocks, now passed in as a JSON string bundle. Twelve strings turned out to already exist and already be translated into all 46 locales while simply not being wired up; using those beat minting new untranslated keys.
- **Three real bugs surfaced during that work.** The starter icon picker carried tooltips for ten icons that do not exist and was missing three that do, so `lightning`, `calendar` and `refresh` were rendering their raw key as the tooltip. The usability-testing page rendered each task type twice with the two copies disagreeing — the badge said "Action + Rate" while the preview said "action then rate". And a learner-facing analytics prompt shipped a British spelling.
- **One visible copy change.** The token-cost page heading was hardcoding the pre-white-label product name and now renders the configured display name, so a default install reads "Saylor Online Learning Assistant — Token Usage & Cost".
- **The spend-category breakdown no longer varies its `GROUP BY` key with the viewer's language** — the SQL now yields a stable slug that PHP maps to a translated label.

**This release does not reduce the BLOCKER count, and no release can.** All 25 are the same two findings, verified false positives across two independent scans. Checking the nine SQL citations against the tagged source: five are real SQL construction, in every case a literal `CASE` expression with all request-derived values bound as placeholders — and the other four point at a docblock comment, a code comment, a blank line, and line 1380 of a 458-line file. The sixteen authentication citations are five endpoints that verify HMAC-SHA256 or a bearer key with constant-time comparison; three of them implement RFC 8058 one-click unsubscribe, which is required to work without a session, so adding a login check would break the unsubscribe mechanism Gmail obliges us to honor. Reviewer replies are drafted; those, not another version, are what can move the gate.

### Testing

- 809 tests, 3,492 assertions, 0 failures.
- Validator suite 36 of 36.
- The comment-only claim was verified mechanically rather than by reading the diff: PHP token-stream hashes with comments and whitespace stripped are identical before and after for every changed file.
- Each templated and extracted page was loaded over an authenticated session and checked for exceptions and for unresolved `[[key]]` placeholders; the two client-rendered card editors were additionally driven headlessly to confirm every label, aria-label, placeholder and confirm dialog resolves.
- Lang parity checked as a set difference in both directions, not by eye.
- Upgrade from v7.0.1 verified with a clean `check_database_schema.php`.

## Part 3: Admin Walkthrough

Core drawer, quiz, voice, analytics, privacy, Soapbox and WSCUC-outcomes flows carry forward from v6.9.8. Two things are new.

### The settings page after the upgrade

Open Site administration → Plugins → Local plugins → AI Course Assistant → Settings on a site with default configuration. The feature toggles are all still there; their configuration is not, until you switch each feature on. Tick "Enable reranking" and its five fields appear inline.

If you had a feature configured before the upgrade, its settings are hidden but not lost — the values are still stored and reappear intact when you switch the feature back on. Nothing needs re-entering.

### Check your inactivity reminders

Worth two minutes on any site that runs learner email. Under Engagement, look at "Inactivity Reminders". If it is unchecked, this upgrade is the point at which that finally takes effect — those weekly emails were going out regardless before now. If you intended them to be off, nothing to do. If you find it unchecked and did want the emails, tick it.

### Rebranding

If you run SOLA under your own name, re-check the settings page after upgrading. Eight controls previously showed Saylor's branding regardless of what you had configured under Branding & UI; they now follow your `institution_name`, `institution_short_name`, `display_name` and `short_name`.
