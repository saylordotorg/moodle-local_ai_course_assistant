# SOLA v7.7.4: Release Notes, Feature Summary, Admin Walkthrough, and Instructor and Learner Walkthrough

## Part 1: Release Notes (6 October 2026)

## v7.7.4 (6 October 2026): chat history no longer shows a stray space before full stops

**Answers reloaded from chat history read "labor ." instead of "labor."** When
SOLA answers from course content it marks each claim with an inline citation,
written after the claim and before its full stop. The live answer turns those
into a source link. The copy saved for history has the markers removed, and the
removal left the space that came before each one, so a reloaded answer showed a
space before nearly every full stop and comma. A citation that sits before
punctuation or a line end now takes those spaces with it. Answers saved before
this release keep their spaces; the fix applies to new answers.

Found while testing the chat as a learner on Moodle 5.3 (alpha.sylr.org).

**Known limit, unchanged:** history doesn't show the "From: ..." source link the
live answer has. The stored copy has never kept source attribution, and keeping
it needs new storage, so it's a separate piece of work.

### Testing

- Three new `protocol_markers_test` cases, from the shapes seen on alpha: a
  citation before a full stop, two citations before a comma, and a citation at
  a line end. All three fail on the previous code and pass on this one; the
  file's other eleven cases are unchanged and pass.
- On Moodle 5.3 (alpha.sylr.org), the fixed class turns
  "labor [[c:0]]. capital [[c:1]] [[c:2]], land" into "labor. capital, land".
  In the browser, two answers saved under the old code show 4 and 2 stray
  spaces after a reload; the first answer saved with the fix in place shows
  none. That answer's raw text wasn't inspected, so whether it carried
  citations isn't confirmed.
- Learner check on Moodle 5.3 with the Student role: consent notice, welcome
  screen, streamed answer with a working source link and four follow-up chips,
  practice quiz with feedback, settings panel; admin-only model pickers and the
  debug inspector are hidden from students.
- PHP lint clean across 613 files; JS checks pass. The full PHPUnit suite runs
  in CI on Moodle 4.5, 5.0 and 5.1.

Plugin version `2026100115`, release `7.7.4`.

## Part 2: Key SOLA Features

What the plugin does as of v7.7.4, for an admin deciding what to switch on.

- **A tutor that knows the course.** Answers come from the course itself, with
  optional semantic retrieval over pages, books, PDF, DOCX, PPTX, H5P and SCORM
  content and video transcripts.
- **Practice built in.** Practice quizzes, flashcards, worked examples, study
  plans with reminders, and essay feedback against a rubric. Practice only,
  never a Moodle grade.
- **Steps back during assessment.** While a learner has a quiz attempt open, the
  assistant is unavailable to them everywhere, including outside the course.
- **Support outside courses** (optional). On the dashboard and site pages it
  answers enrolment, certificate and technical questions from a support course
  and the FAQ, with its own three starters, and can hand off to Zendesk.
- **46 languages**, with automatic reply-in-your-language, speech input and
  output, and an optional live voice mode. Works on phones, including with
  Moodle's menu drawer open.
- **Any provider.** Gemini, OpenAI, Claude (including Opus 5.5 and Sonnet 5.5),
  DeepSeek, Mistral, xAI, MiniMax, OpenRouter, Together, Ollama, Moodle's own AI
  subsystem, or any OpenAI-compatible endpoint. Failover, a premium tier for hard
  turns (Claude Sonnet 5, benchmark-backed), and spend caps per course.
- **Costs you can see.** A model registry with prices and their sources, a daily
  price-drift check, token analytics, cost anomaly alerts and benchmarks.
- **Safe defaults.** Nothing contacts a third party until an admin configures
  it: remote configuration, the Python sandbox runtime and the CDN delivery all
  default to off. The assistant opens by itself only on course pages, and only
  if an admin turns auto-open on.
- **Keys encrypted at rest.** Provider keys and every other secret are stored
  with Moodle's own encryption, so a database backup alone doesn't reveal them.
- **White-label.** Four settings rename the whole product, in every language.
- **Instructor views.** Analytics, a review queue for learner feedback, Learning
  Radar, transcripts with pseudonyms, and surveys with validated rating scales.
- **Python sandbox** (per course). Runs in the learner's browser, never on the
  server, and shows the full error when code fails.
- **Soapbox** remains deprecated and will be removed in v8.0.0; its replacement is
  the standalone PresenterAI activity.

## Part 3: Admin Walkthrough: upgrading from v7.5.7

About twenty minutes. This is written for a site moving from v7.5.7, the version
Saylor's production runs, straight to v7.7.4, and covers what an admin will
notice. The first three steps are the ones that can change behaviour on the day.

### 1. Remote configuration is off unless you set it

Go to Site administration, Plugins, Local plugins, AI Course Assistant, then the
**Settings** page. Find **Remote config URL**. If your site never set it, the
upgrade cleared it and remote configuration is now off. If you had set your own
URL, it's untouched and still active.

### 2. The Python sandbox needs a runtime location

If any course uses the code sandbox, go to **Surveys and feedback** and find the
Pyodide runtime location. It's empty by default, and the sandbox stays off until
it's set: the old version loaded the runtime from a public CDN, which sent every
learner's IP address to a third party. Point it at a copy you host, or at a CDN
you've chosen deliberately. Then open the sandbox in a course, run some code
that fails, and check you see the real Python error rather than the bare word
"PythonError".

### 3. Your settings bookmarks may land on the wrong page

The settings used to be one long page; they're now eleven. A bookmark to the old
page opens **Settings**, which no longer holds the provider, model or API key.
Those are on **AI provider and models**
(`/admin/settings.php?section=local_ai_course_assistant_ai`). Click through a
few pages and notice that each opens with its own section heading.

If you run with debugging set to DEVELOPER, the settings category page now loads
normally. Before v7.6.4 the page's show-and-hide rules could exceed a size limit
Moodle enforces at that debug level and make the page return an error.

### 4. Check the retry limits

Open **Resilience and operations**. Backend retry attempts now accept 0 to 10,
and the maximum wait 0 to 30 seconds. If a value you saved earlier is outside
that range, the plugin already brings it into range when it reads it, and the
form will flag it next time you save, so you can choose a value on purpose.

### 5. Look at your surveys

Open the **Survey Editor**. Rating questions must now run from 1 to 10, low end
first. A survey stored with a backwards or oversized scale was repaired once
during the upgrade, and the upgrade output lists each change. Results keep every
answer recorded under the old scale, and the average is shown against the
question's own scale instead of always out of 5.

### 6. Try the system prompt reset in another language

Switch your admin language to French or Spanish, open **AI provider and models**,
and press **Reset to template** under the system prompt. The default should
appear with its accents intact. On earlier versions it came back garbled in 37
of the 46 languages. Don't save unless you mean to.

### 7. Open the chat

Open a course and start a conversation. A short exchange now sits just above the
box you type in rather than at the top of the drawer. If support mode is on,
open the dashboard: the starters there are for technical trouble, finding your
way around, and enrolment and certificates, not course work. The assistant no
longer opens by itself there, even with auto-open on; that setting now applies to
course pages only. On a phone, open Moodle's menu, then the assistant, and tap
the text box: it should take your typing.

### 8. If you use Claude

The newest Claude models now work, and Opus 5.5 is priced correctly. The premium
tier for hard turns stays on Claude Sonnet 5: Opus 5.5 was benchmarked against it
and scored lower on guiding students, at three times the cost.

### 9. Your keys are now encrypted, so back up the key that opens them

From v7.7.3, provider keys and every other secret are encrypted at rest with
Moodle's own encryption. The upgrade encrypts the keys you already have, so
nothing needs entering again on this site, and the upgrade output says how many
it encrypted. Open **AI provider and models**: the API Key field now reads
"Click to enter text" or shows that a value is set, instead of a masked box. To
change a key, click it and type the new one.

The keys in the **Voice providers** table are encrypted per row the same way.
Open that table and check that each key box shows a long encrypted value rather
than your key; saving the page without changes keeps them as they are.

Three things follow from this:

- Back up `moodledata/secret/key/` along with the database. Without it, a
  restored database can't decrypt the keys.
- A database copied onto another site, a staging refresh of production for
  example, can't read production's keys. The assistant treats them as unset
  there, so enter that site's keys again.
- Keys typed into the free-text **comparison providers** and **spend guard
  fallback** lists are still plain text. If you use those lists, treat database
  backups as containing those keys.

A key set in `config.php` through `$CFG->forced_plugin_settings` keeps working
and isn't touched.

### 10. Check the suite you'd use after any provider change

From a shell on the server, run the jailbreak suite against a course:

```bash
sudo -u www-data php local/ai_course_assistant/admin/cli/jailbreak_test.php --courseid=<id>
```

It costs a few cents on a Flash-class model. The release gate is 0 FAIL. Every
FAIL and every REVIEW now prints the full prompt and response, so you can judge
each one rather than guess from a 200-character excerpt. Run it again after you
change provider, model or system prompt.

While you're on **AI provider and models**, note that as an admin you see LLM and
Model pickers under the chat's text box, for trying another provider without
changing the site setting. Learners never see them.

### 11. Privacy requests reach more data

Learner data export and deletion now include email opt-outs and the consent and
download records kept outside any course. Run a data export for a test learner
to see them.

## Part 4: Instructor and Learner Walkthrough

About ten minutes, for a teacher or a learner rather than an admin. It covers
what someone using the assistant in a course will notice after the upgrade from
v7.5.7. None of it needs a setting changed.

### For learners

1. **Open a course and say hello.** The assistant's replies now sit just above
   the box you type in, the way a messaging app works, instead of starting at
   the top of the drawer. Long replies still open at their first line so you
   can read from the start.
2. **Try it on your phone.** Open the course on a phone, open Moodle's menu,
   then open the assistant and tap the text box. It takes your typing. Before
   v7.7.2 the menu kept the cursor, so nothing could be typed.
3. **Visit the dashboard.** If your site has support mode on, the assistant is
   there too, but it doesn't open by itself any more. When you open it, its
   three starters are about technical trouble, finding your way around, and
   enrolment and certificates. It won't offer course-work help outside a
   course, because there's no course for it to draw on.
4. **Start a quiz attempt.** While an attempt is open, the assistant steps back
   everywhere, including outside the course. It comes back when the attempt is
   submitted, and even then it won't give out answers to graded questions; it
   will help you work through the ideas behind them.
5. **Run some Python, if your course has the sandbox.** Write code that fails.
   You now see the real Python error and its line, not just the word
   "PythonError".
6. **Download your data.** Open the assistant's gear icon, then **Settings**,
   then **My SOLA data**. The download now includes your email opt-out and the
   consent and download records kept outside any course.

### For instructors

1. **Thumbs-down feedback stays in your review queue.** A learner's thumbs-down
   used to drop out of the queue once their conversation grew past the history
   limit, which hit the longest, most engaged conversations hardest. It now
   stays until you deal with it.
2. **Surveys work with any sensible scale.** Rating questions run from 1 to 10,
   low end first. A survey saved with a backwards scale was repaired once during
   the upgrade, and results keep every answer recorded under the old scale.
3. **Course settings.** If your course has its own API key (set on the
   course's AI settings page, which editing teachers can open), it's now stored
   encrypted. Nothing changes in how you use it: the course settings page still
   only says whether a key is stored, and leaving the field blank keeps it.
4. **Auto-open is about your course pages.** If you've switched auto-open on
   for your course, it opens the assistant the first time a learner lands on
   the course, as before. It no longer has any effect on the dashboard or other
   site pages.
