Version 7.6.2 (build 2026100103)

A maintenance release. Nothing a learner sees changes. Five things that were
quietly wrong are now right, four of them about data the plugin held that the
people it belonged to could not reach.

An email address no data request could reach (#284). The opt-out table
stores a learner's email. The only thing that writes one is the unsubscribe
link, followed by someone who is not logged in, so every real opt-out stored no
owner. Both discovery methods and both erasure paths look the owner up by id, so
the address survived a subject access request, survived an erasure request, and
survived deletion of the account.

The row is attributed at the point of opt-out now, claimed only when exactly one
live local account holds that address: two accounts means no single owner, and
guessing would attach one person's opt-out to another person's data request. An
upgrade step backfills what already exists under the same rule.

Attributing the row was necessary and not sufficient. It has no course, every
discovery query joins a course, and the erasure method only runs for a context
discovery returned, so the provider gained a system-context path.

Audit rows holding IP addresses, unreachable (#285). Consent and
self-download are recorded outside any course, and the row carries the learner's
IP address and browser. Every audit query keyed on the course, so course zero
matched none of them. Fixed by reusing the path #284 needed.

Clearing a setting did not take effect for an hour (#282). The remote
configuration URL had no update callback, so an administrator who cleared the
field to switch the feature off kept getting remote values, including the system
prompt their learners talk to, until the cache expired. The upgrade step purged
that cache for exactly this reason; the admin form had no equivalent.

A thumbs-down disappearing from the review queue (#283). The conversation
cap trims the oldest messages and left their ratings behind, and every consumer
joined through the message. So a learner's negative rating left the instructor
review queue the moment their message aged out: the longer and more engaged the
conversation, the more likely the feedback was lost.

The rating keeps a copy of the text it was about. Only three of the five
consumers changed: attributing ratings to a module or to a model needs the
message, and an orphaned rating has neither, so those two keep their stricter
join and a test keeps them that way.

Every embedding was stored twice (#266). A packed vector and a JSON copy
about three times its size that nothing read. Across the dev fleet it was 443 MB
of 463, and it was rewritten on every index, so it grew back after any cleanup.
The JSON is no longer written.

The column is deliberately not dropped and existing rows are not cleared. On two
of five dev sites, 1,054 rows held the JSON and no packed copy; for those the
JSON is the vector, and removing it would destroy the embedding and cost a paid
re-embed with search quietly degraded. Retrieval keeps its fallback for those
rows, and the backfill tool converts them.

2,014 tests, 0 failures, 7 skipped. Validators 36 of 36.

UPGRADE NOTES

Two upgrade steps run automatically: one attributes existing email opt-outs to
their owner where that can be determined unambiguously, and one adds a column to
the message-ratings table and backfills it from the messages still present. No
administrator action is required and no setting changes.

If you are upgrading from 7.5.x rather than 7.6.x, read the 7.6.0 notes as well.
That release made remote configuration opt-in and has an upgrade note about
checking your Model setting first.
