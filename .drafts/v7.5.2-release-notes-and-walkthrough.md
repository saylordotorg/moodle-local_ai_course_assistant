# SOLA v7.5.2 — Release Notes, Feature Summary, and 20-minute Admin Walkthrough

## Part 1: Release Notes (19 September 2026)

**Soapbox is deprecated and will move to a plugin of its own. Everything it stores is now deleted when it says it is, matched the way it says it is, and announced to the people who read screen readers.**

- **Soapbox is deprecated, and nothing about it changes yet.** It is moving out of SOLA and into PresenterAI, a separate Moodle activity plugin that appears in the activity chooser and adds a choice of storage and of AI provider. A presentation activity does not really belong inside a chat assistant: it cannot appear in the activity chooser, cannot be graded like an activity, and every site that wants presentations has to install a whole learning assistant to get one. This release changes no behaviour and deletes nothing. The code is scheduled for removal in v8.0.0, and no release removes it until PresenterAI can import existing recordings and scores. The database tables come out separately and later, because Soapbox writes no gradebook entry, so those tables are the only copy of a learner's presentation record. Administrators and teaching staff get a notice; learners get none, because nothing changes for them and telling a student mid-course that their work sits in a retiring feature produces worry and nothing to do about it. `.wiki/Migration-to-PresenterAI.md` carries the timeline.
- **A description of a learner's body no longer outlives the video it describes.** v7.5.1 sampled six stills for body-language feedback and deleted them with the recording at the retention deadline. It kept the prose the model wrote about them, on the score row, which deliberately survives retention. So a description of where a named learner's hands were was kept indefinitely, in a field nothing in the product reads, while the frames it came from were deleted on schedule. It also made the privacy notice false: that notice promises the video goes "together with the still frames used for body-language feedback". It goes now.
- **A course purge left the recording, the transcript and the video behind.** Deleting a course's data deleted seven tables including the scores and never touched the recordings table. The score vanished, which is the part anyone would look at, so the purge appeared to work, while the video stayed in the bucket and the transcript stayed on the row. This predates the body-language work and affected audio-only sites too.
- **A criterion name is now matched the same way everywhere it is matched.** Scoring decides three things from a criterion name: whether the model may score it, what maximum to divide by, and which course outcome the attempt records against. The first two ignored case and spacing; the third did not. So a model answering "evidence" for a rubric row called "Evidence" was scored, was shown to the learner, and silently recorded nothing against the outcome. Where two rubric rows now collide and disagree, nothing is recorded at all rather than one being picked by array order: an outcome attempt is permanent, staff-visible only, and a self-paced learner can neither see nor appeal one written against the wrong outcome. The rubric editor refuses to save such a rubric, because that is the only place a person can see the problem.
- **One rule for whether a criterion counts, instead of four.** The "assessed" flag had four hand-written implementations giving three different answers for the values 0, "0" and "", so a score could count a criterion that the very table printing that score greyed out. There is now one implementation, and a test that fails if anyone writes a fifth.
- **The reason a criterion was not assessed now reaches a screen reader.** It sat in a `title` attribute on a badge that already had visible text, so most screen readers never announced it and the explanation was mouse-only. In self-paced courses with no instructor, that sentence is the only thing between a learner and the belief that they were marked down for something nobody looked at.
- **Four tables that record which administrator configured the site are declared to the privacy API.** None holds learner data, and none is exported or erased, because deleting them would remove the institution's model pricing, its price feeds, its benchmark history, and would reshape a presentation assignment other learners are working against. Moodle core's own privacy test was failing on three of them; the guard added here found the fourth.
- **The JavaScript guards in `tests/js` actually run in CI.** Three of them sat in the repository invoked by nothing. One checks that `amd/build/chat.min.js` was rebuilt from its source, which is the check that would have caught `sse_client.min.js` sitting two months behind.

### Testing

- Full PHPUnit suite green. Validator suite 36 of 36.
- Moodle core's own privacy suite green (1631 tests), which is where the undeclared tables surfaced.
- PHP lint clean on every modified file; all three `tests/js` guards exit 0.

## Part 2: Key SOLA Features

Carried forward from v7.5.0. One new capability: **Soapbox body-language feedback** (`soapbox_gesture_vision`, off by default). The two visual criteria it scores are fixed in this release; the authorable rubric types remain speech, conversation and pronunciation. No other feature changes.

## Part 3: Admin Walkthrough

### 1. Record a Soapbox attempt and read the feedback

Open a Soapbox presentation activity as a learner, record a short attempt, and wait a few minutes.

**Expected:** a "Show my feedback" panel on the attempt row, listing every rubric criterion with a score and a written comment, the overall note, and three tips. Before this release none of it was shown, although all of it was being generated.

### 2. Download the recording

Click Download on the same row.

**Expected:** the file saves. Before this release the link opened the video in a browser tab, which is not the same thing as being able to keep it.

### 3. Check the deletion date

Look at the Deletes on column.

**Expected:** a real date, seven days after recording by default, and the paragraph above the recorder says the same thing in words. Change `soapbox_retention_days` and confirm new recordings follow the setting.

### 4. Turn on body-language feedback

Site administration → AI Course Assistant → **Soapbox body-language feedback**. Record a video attempt with your camera on, head, shoulders and hands in frame.

**Expected:** two extra criteria in the feedback, about gestures and about eye contact, each naming something specific that was visible.

### 5. Record with the camera pointed away, and check the arithmetic

Record again with the camera facing the ceiling.

**Expected:** the two visual criteria show a "Not assessed" badge rather than a zero, the summary line reads "the average of the 5 criteria that were assessed, out of 7", and a sentence explains why that section is missing. The overall score is the average of what was actually judged.

### 6. Confirm an audio-only assignment is untouched

Run an audio-mode assignment with the feature on.

**Expected:** five criteria, no visual rows, and **no** sentence about cameras. There is nothing to explain when video was never part of the assignment.

### 7. Confirm the default is quiet

Turn the setting back off and record a video attempt.

**Expected:** five criteria, 100% denominator, and no mention of body language anywhere in the saved feedback. The pre-merge review caught this one: an earlier build told every learner on every site that their camera could not be read.
