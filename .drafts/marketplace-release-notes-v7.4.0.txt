v7.4.0 makes model and pricing information maintainable without a code change, and fixes two defects reported by an external user on Moodle 5.1.

The problem that prompted it: the plugin's primary chat model had no rate-card entry. Rate lookup is a longest-prefix match, so it resolved to nothing, cost estimation returned null, and every consumer treats null as "skip" - meaning all chat spend computed as zero. No spend cap could trip and every cost figure was a floor rather than a number. Adding one row would have fixed the moment and drifted again next quarter, so this release replaces the constant with a registry.

The registry resolves three layers in order - the committed baseline, the existing override setting, then a per-model database table that wins - and records which layer supplied each price, who set it and when. An automated feed can no longer overwrite a price a human entered by hand; previously the weekly refresher replaced the whole override blob and silently destroyed such corrections. Pricing sources are themselves database rows carrying a declarative parse specification, so adding a new vendor feed is an admin form rather than new code. A daily task compares each source against the registry and proposes corrections without ever applying them silently; its highest-severity finding is not that a price moved but that a model appearing in real traffic has no price at all.

Benchmark results are now stored rather than discarded. The existing golden-set harness already measured quality, cost per call and time-to-first-byte and then wrote them to a file; those runs now persist, any registered model can be benchmarked from the admin interface, and a recommendation engine compares the configured model against measured alternatives. It declines to compare when the sample is too small or spans a plugin release, and says so, rather than substituting a neutral score.

Retrieval changes from a benchmark readout: the reranker is now length-gated, which measured better than always-on while costing about a third less; asymmetric query and document embedding has been dropped in favour of a single shared embedding space after failing to reproduce twice; voyage-4-large at 2048 dimensions is supported, with adoption implemented as a per-course migration that writes new vectors alongside the old ones so the live index keeps serving throughout.

Two defects reported in issue #218 are fixed. A comment quoting a literal PHP closing tag ended the course-settings page's PHP block early, so the page served part of its own source; the visible warning was the lesser half, because the same failure removed the only interface for clearing a per-course API key. No credential was exposed. Separately, the shipped default provider called a core AI constructor whose signature changed in Moodle 5.0, making it fatal on every Moodle 5.x release; because that provider is what the default configuration resolves to, affected sites had no working configuration at all. The continuous integration matrix now covers Moodle 5.0 and 5.1 in addition to 4.5, which is what would have caught it.

Quality gate: 1,469 automated tests with no failures, 36/36 validators, 46/46 locales complete, and an HTTP smoke covering 35 pages.
