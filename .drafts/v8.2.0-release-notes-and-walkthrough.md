# SOLA v8.2.0: Release Notes, Feature Summary, and Admin Walkthrough

## Part 1: Release Notes (21 November 2026)

## v8.2.0 (21 November 2026): Gemini Live voice, and an avatar that follows the voice

**Why this release exists.** Live voice mode ran on OpenAI's Realtime API only. Google's Gemini Live API offers low-latency two-way speech with native audio, and Google is retiring its native-audio preview (gemini-2.5-flash-native-audio-preview-12-2025) on 31 March 2027 in favour of gemini-3.8-live. This release adds Gemini Live as an optional Realtime provider, with the cost guardrails a per-second-billed voice session needs, and makes SOLA's built-in avatar move with the voice. Paid avatar vendors (D-ID, HeyGen, Tavus, Synthesia) are unchanged.

**Switching it on.** A new setting, **Allow Gemini Live for voice mode** (`gemini_live_enabled`, off by default, under **Advanced > Prompt, voice and display** next to the voice providers), lets a `gemini` row in **Voice providers** serve live voice. The row's key is used; there is no new key field. With the setting off, a gemini row is text to speech only, exactly as in 8.1.0. Pick the gemini row as the **Active Realtime provider** and keep **Enable Voice Mode** on.

**What reaches the browser, and what doesn't.** The site's Gemini key never does. When a learner starts voice mode, the server mints a single-use Gemini ephemeral token that can open a session for one minute and stops working 30 seconds after the session limit, locked to the model, the grounded tutoring instructions (the same voice-mode prompt and the same special-token clean-up as OpenAI voice), audio output, the voice and transcription of both sides. The browser gets the token, the model name and the limits. All the existing checks still run first: the `:use` capability, the six-per-five-minutes mint limit, Voice Mode on, the emergency kill switch and the voice spend cap.

**Cost guardrails.** Google bills a live session for as long as it is open, roughly $0.70 to $1.40 per hour of conversation by third-party estimates (not checked against Google's price list). Three limits, each with a safe default, sit behind the toggle:

- **Longest Gemini Live session** (10 minutes, 1 to 30): the browser ends the session, and the token's own expiry ends it even if the page is tampered with.
- **End an idle Gemini Live session after** (90 seconds, 15 to 600): no speech from either side for that long ends it.
- **Gemini Live minutes per learner per day** (30, 0 for none): counted on the server from midnight in the server's time zone. A session the browser never reports counts its full length, and a new session is cut short to fit what's left; with under a minute left, live voice is refused and the conversation continues in the regular voice mode.

**Spend.** Each session writes one row in the voice spend bucket (interaction type `gemini_live`), and when it ends the browser reports its length and Google's token counts onto that row, once, clamped to what the server can believe. **No Gemini Live price is in the repo**, so these rows are unpriced: they show in the model registry's unpriced banner and the price-drift check, not as free. One exception: `gemini-2.5-flash-native-audio-preview-12-2025` matches the `gemini-2.5-flash` chat price and is priced as chat text, which is wrong for audio. Add a model registry row with Google's audio price before relying on the spend caps for live voice.

**In the browser.** A new module, `gemini_live.js`, with the same interface as the OpenAI one: the microphone goes through an AudioWorklet as 16 kHz audio, the model's 24 kHz audio plays without gaps, and when the learner talks over the model its audio stops at once. Both sides are transcribed into the chat. Gemini Live answers in audio only, so the four suggestion chips after a reply are the fixed ones (Tell me more, Give me an example and so on) rather than the model's own, and the Gemini prompt tells the model never to say tags aloud. If live voice can't start (an old browser, a network error, a refused token, the daily allowance), a conversation continues in the regular turn-based voice mode with a short note; pronunciation practice shows the error, since it needs live audio.

**The avatar.** The built-in SVG avatar's mouth opens with the voice and its head lifts and sways slightly (at most 1.5 pixels and 2 degrees), for live voice and for read-aloud answers alike, driven by the audio on its way to the speakers. No new dependency, no network call. It stays still when **Avatar animation** is off or the learner's system asks for reduced motion, and it's hidden from screen readers: the transcript is the content.

**OpenAI Realtime models.** OpenAI shuts down `gpt-realtime-mini` and `gpt-realtime` on 20 January 2027 (successors `gpt-realtime-2.1-mini` and `gpt-realtime-2.1`, from OpenAI's deprecation notice as fetched on 21 November 2026). Until now SOLA named `gpt-realtime-mini` in the server's Realtime URL and in the browser code. The voice model catalog now lists all four, the OpenAI Realtime default is `gpt-realtime-2.1-mini`, and from 20 January 2027 a row still naming an old model is sent to its successor. Voice provider rows gain an optional **Realtime model** column (blank uses the default; for a gemini row, blank uses the Gemini Live model setting). The browser no longer has a model of its own: it uses the URL the server sends. Text to speech (tts-1) and speech recognition (whisper-1) are unchanged in this release.

**Upgrade notes.** No schema change and no upgrade step. One new web service function (`local_ai_course_assistant_record_live_usage`), registered on upgrade. Thirteen new admin and error strings are English only for now; `settings:voice_providers_desc` changed (it was already English only). New JavaScript: `gemini_live` and `avatar_motion`; `chat`, `ui` and `repository` were rebuilt.

### Not verified

The token request is isolated in `classes/voice/gemini_live_token.php`, the message handling in `amd/src/gemini_live.js` (`classify()`), so a mismatch is fixed in one place each.
- Whether `usageMetadata` is per turn or cumulative: SOLA sums it, which over-counts if Google sends running totals.
- The model id `gemini-3.8-live`, its voices and the shutdown date come from Google's notice as relayed by the site owner.
- Real audio: echo, barge-in timing, iOS Safari, and the avatar's look were not tried in a browser.
- Prices (see Spend).

### Live check (owner, about 15 minutes, dev site only)

1. On the dev site (8.2.0), **Site administration > Plugins > Local plugins > AI Course Assistant > Advanced > Prompt, voice and display**. In **Voice providers** add a row: provider **Google Gemini**, a Gemini API key that may be used for testing (not the production key), label `gemini-live`, Realtime voice `Puck`. Save.
2. Tick **Allow Gemini Live for voice mode**, leave the model blank, keep the defaults (10 minutes, 90 seconds, 30 minutes a day). Save, then set **Active Realtime provider** to `gemini-live` and make sure **Enable Voice Mode** is on. Save.
3. Open BUS101 as a student in Chrome over HTTPS with the browser's developer tools on the Network tab (filter WS). Open the Voice tab and start a conversation.
   - Look for: the `get_realtime_token` call returns `provider: gemini`, a `token` starting `auth_tokens/`, no key starting `AIza`; a WebSocket to `generativelanguage.googleapis.com` whose first frame is `{"setup":...}` and whose first reply is `setupComplete`. If the token call fails, the learner sees "Live voice couldn't start right now" and the regular voice mode starts; with developer debugging on, the response's debuginfo holds Google's own message (keys and tokens redacted). The token request shape in `gemini_live_token.php` is the first suspect.
4. Say: "Can you explain what a balance sheet is?" Look for: the answer in under a second or two, your words and SOLA's words appearing in the chat, the avatar's mouth moving with the voice.
5. While SOLA is talking, say "Wait, stop." Look for: SOLA's audio stopping at once and a new answer to the interruption.
6. Say nothing for 90 seconds. Look for: the note that the session ended because nobody spoke.
7. In the database: `SELECT message, prompt_tokens, completion_tokens, model_name FROM mdl_local_ai_course_assistant_msgs WHERE interaction_type = 'gemini_live' ORDER BY id DESC LIMIT 3;` Look for `[Gemini Live session: Ns]` with non-zero tokens and `gemini-3.8-live`.
8. Fallback: set the model to `gemini-0-live`, save, start voice again. Look for: an error from the token call or the socket, then the note that the conversation uses the regular voice mode, and the regular voice mode working.
9. OpenAI Realtime (if the site has an OpenAI voice row): set the Active Realtime provider to it, start voice, and check in the Network tab that the WebSocket URL ends `?model=gpt-realtime-2.1-mini` and the session answers. If OpenAI refuses that model, type `gpt-realtime-mini` in the row's **Realtime model** column (callable until 19 January 2027) and say so in the release thread.
10. Put it back: clear the model, untick **Allow Gemini Live**, or set the Active Realtime provider back. Remove the test row if the key shouldn't stay.

## Part 2: Key SOLA Features

What the plugin does as of v8.2.0, for an admin deciding what to switch on.

- **A tutor that knows the course.** Answers come from the course itself, with
  optional semantic retrieval over pages, books, PDF, DOCX, PPTX, H5P and SCORM
  content and video transcripts.
- **Practice built in.** Practice quizzes, flashcards, worked examples, study
  plans with reminders, and essay feedback against a rubric. Practice only,
  never a Moodle grade.
- **Steps back during assessment.** While a learner has a quiz attempt open, the
  assistant is unavailable to them everywhere, including outside the course.
- **Support outside courses** (optional). On the dashboard and site pages it
  answers enrolment, certificate and technical questions from a support course
  and the FAQ, with its own three starters, and can hand off to Zendesk.
- **Readable answers.** Headings, lists, tables, quotes and code render in the
  chat, and an answer that runs out of room says so rather than stopping
  silently.
- **46 languages**, with automatic reply-in-your-language, speech input and
  output (OpenAI, xAI or, since 8.1.0, Gemini text to speech), and an optional
  live voice mode (OpenAI Realtime or, since 8.2.0, Gemini Live, with session,
  idle and daily limits). The built-in avatar's mouth and head follow the voice.
  Works on phones, including with Moodle's menu drawer open.
- **Any provider, one table of keys.** Gemini, OpenAI, Claude (including Opus
  5.5 and Sonnet 5.5), DeepSeek, Mistral, xAI, MiniMax, OpenRouter, Together,
  Ollama, Moodle's own AI subsystem, or any OpenAI-compatible endpoint. Every
  provider's key, models and base URL live in one **Providers and keys** table,
  so you can add or change a key without touching the default provider.
  Embedding, Rerank and Voice can use a row's key instead of a pasted copy.
  Failover, a premium tier for hard turns (Claude Sonnet 5, benchmark-backed),
  and spend caps per course.
- **Keeps up with new models.** It knows what each model accepts from data
  rather than name checks, fixes a rejected request by itself, and (unless an
  admin turns it off) tests newer models nightly and switches to one that's
  the same price or cheaper and at least as good, rolling back if live answers
  get worse. Voice models follow a catalog of shutdown dates and successors, so
  a retired voice model is never called, and admins are warned 45 days ahead.
- **Costs you can see.** A model registry with prices and their sources, a daily
  price-drift check, token analytics, cost anomaly alerts and benchmarks.
- **Safe defaults.** Nothing contacts a third party until an admin configures
  it: remote configuration, the Python sandbox runtime and the CDN delivery all
  default to off. The assistant opens by itself only on course pages, and only
  if an admin turns auto-open on.
- **Keys encrypted at rest, never shown, and replaced in one step.** Provider
  keys, the Voice providers table, webhook URLs and every other secret are
  stored with Moodle's own encryption, so a database backup alone doesn't
  reveal them. No settings page ever shows a key: a saved one reads "Saved, ends
  in ab12", and the settings-changed notice and Moodle's configuration log hide
  secrets too. A command lists where each key is stored (by its last four
  characters only) and replaces one key everywhere in a single transaction, and
  a Reports > Status check flags a key kept in several places.
- **White-label.** Four settings in Essentials > Branding rename the whole
  product, in every language: the widget and its tooltips, the prompts the
  model sees, alert and learner emails, default surveys and admin pages.
- **Instructor views.** Analytics, a review queue for learner feedback, Learning
  Radar, transcripts with pseudonyms, and surveys with validated rating scales.
- **Python sandbox** (per course). Runs in the learner's browser, never on the
  server, and shows the full error when code fails.
- **PresenterAI replaces Soapbox.** Soapbox has been hidden and switched off
  since 7.12.5; its data, playback and privacy handling stay until PresenterAI
  has imported it.

## Part 3: Admin Walkthrough Script: Gemini Live voice (about 5 minutes, conversational)

Written to be read aloud while you click. It assumes a test site on 8.2.0, an admin login, a course with the assistant on, and a Gemini API key that may be used for testing. Don't use the production key.

### 1. Turn it on (about 1 minute)

Open **Site administration, Plugins, Local plugins, AI Course Assistant**, then **Advanced, Prompt, voice and display**. "Gemini Live uses the same Voice providers table as Gemini speech. I'll add a gemini row with a test key and the voice Puck." Save. "Now the new switch, Allow Gemini Live for voice mode. It's off by default, because the learner's audio goes to Google and Google bills every second a session is open." Tick it and save; three limits appear. "Ten minutes a session, ninety seconds of silence, thirty minutes a learner a day. A session the browser never reports counts in full, so the daily limit can't be dodged." Set **Active Realtime provider** to the gemini row and save.

### 2. Talk to it (about 2 minutes)

Open the course as a student, go to the Voice tab and start. "The page asked the server for a token. The server checked the kill switch, the spend cap and the learner's allowance, then got Google to issue a one-time token locked to this model and these instructions. The browser never sees our key." Ask a question about the page, then interrupt halfway through an answer. "It stops the moment I speak, and both sides are written into the chat." Point at the avatar. "The face is ours, drawn in the browser. Its mouth follows the audio, and it stays still for anyone whose system asks for reduced motion."

### 3. When it can't start (about 1 minute)

Set **Gemini Live model** to a name that doesn't exist, save and start voice again. "The live session can't start, so the learner gets a note and the regular voice mode instead of a dead button." Put the model back to blank.

### 4. What it cost (about 1 minute)

Open the token analytics or the spend dashboard. "Each live session is one row in the voice bucket with Google's token counts. There's no Gemini Live price in the registry yet, so it shows as unpriced rather than free. Add the price before you trust the voice spend cap with it."
