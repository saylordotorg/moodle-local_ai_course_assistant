Version 7.6.8 (build 2026100109)

One wrong number in the retry settings could tie up part of the server for
hours. This release closes that, in three layers.

When an AI provider is busy it asks the plugin to wait and try again. Two
settings control that: how many times to retry, and the longest wait to accept.
The retry count had a minimum but no maximum. Mistyped as 20000, with a busy
provider, a single request would sit waiting for about 17 hours. That wait
doesn't count as running time, so PHP's time limit never stopped it, and the
server process it held could serve nobody else. A few learners hitting a busy
provider at once could use up every process the site has. The longest-wait
setting had the same gap.

The settings page now refuses a value outside the allowed range, 0 to 10
retries and 0 to 30 seconds, and says what the range is. A value that never
went through that page, such as one saved earlier or forced in the site config,
is brought back into range whenever it's read. And the total time one request
may spend waiting is capped at 30 seconds, because even the highest allowed
settings would otherwise hold a process for five minutes.

The chat and embedding paths now take these limits from one shared place, so
they can't drift apart.

If your site already has an out-of-range value, it is safe from this release
onward. The settings page will flag it the next time that page is saved.

Tested: 2,067 automated tests with no failures, the security validator corpus
at 36 of 36, and PHP lint clean across 606 files. Six of the new behaviours
were checked by deliberately reintroducing the bug and confirming the test
failed. Continuous integration covers PHP 8.1 through 8.3 against Moodle 4.5,
5.0 and 5.1, on both MariaDB and PostgreSQL.
