# SOLA v7.2.7 — Release Notes, Feature Summary, and 20-minute Admin Walkthrough

## Part 1: Release Notes (31 August 2026)

**The staging pass, closed.** Ten findings from the seventh testing pass, the
first run against Catalyst staging rather than the dev fleet. None of these is a
new regression — every item has been shipping, most of them for months. They
surfaced because the pass went at a real site with real courses and a real
student account.

### Fixed

- **`send_message` web service crashed after paying for the model call.** The
  registered external function threw a `TypeError` on argument 11 for every
  caller, *after* the provider request completed. Each failed call billed an AI
  request, committed the student's question to their visible history with no
  answer under it, and wrote no audit row. Now passes the same interaction type
  the SSE path writes, records a `message_sent` audit row, and returns a generic
  message rather than an internal class path when something fails.
- **Per-course AI config was backed up but never restored.** `aica_course_settings`
  restored; `aica_course_configs` did not. An instructor-authored per-course
  system prompt was discarded by every course-rollover restore while every other
  SOLA setting survived. Now a field-level merge: empty fields are filled from
  the backup, populated ones are never clobbered.
- **The support FAQ is retrievable instead of always-on.** It was assembled into
  every prompt at ~4,451 chars, most of the fixed overhead crowding out
  retrieved course content. Now indexed as chunks alongside course material.
  Fail-safe in both directions — RAG off, empty content, stale index, or no
  chunks all fall back to the previous inline injection unchanged.
- **Auto budget mode with nothing to derive from now says so.** Mode `auto` with
  no chat model and `backend_context_tokens = 0` silently used the fixed number
  while the label claimed derivation. Staging was truncating 89.5% of turns and
  dropping a whole section from 57.9%. The settings page now warns directly and
  names both remedies.
- **Prompt metrics records which section was dropped**, not only the rate. A
  57.9% drop rate means something very different if the section leaving the
  prompt is `safety` rather than `faq`.
- **The consent banner sat on top of the widget footer.** A first-run student's
  very first click opened Send Feedback. It is now a true modal that seals the
  footer with `inert` while consent is pending, and it is fully opaque, so the
  layer beneath no longer bleeds through the privacy notice.
- **The quiz setup panel mounted onto the drawer root**, so it painted below the
  footer and the tab bar. It now mounts inside the drawer's content region.
- **A quiz-lock refusal now writes its own audit row** (`quiz_lock_refused`,
  with course and attempt id) — the one event an academic-integrity review would
  actually query on, and the only one the vocabulary was missing.
- **The dormant language banner** was collapsed to 1px rather than removed,
  leaving two invisible, unannounced buttons in the tab order that would change
  the assistant's language if activated (WCAG 4.1.2). It is now `inert` when
  dormant and is not rendered at all without a message.
- **Enter-to-send gained a delegated fallback** on the widget root, plus a
  console warning when the composer cannot be found, so a missed direct binding
  can no longer fail silently.

### Changed

- Analytics tiles are now **TOTAL ENROLLED** and **MSGS / ACTIVE USER**. Nothing
  was miscalculated — messages per student has always divided by active AI users
  — but on staging the tiles read 435,389 students beside 2 active users, which
  cannot be reconciled as they were labeled. The two dashboard tables carrying
  the same ambiguous column now resolve their headers through the translated
  string bundle as well.

### Known follow-ups

- Four dashboard tables still ship hardcoded English headers (Metric / AI Users
  / Non-Users, Type / Count / %, Keyword / Frequency / Category, Message Excerpt
  / Comment / Hallucination? / Date). Found while fixing the two above; not
  fixed here.
- 354 lang keys per locale remain untranslated across the 45 non-English files.
  This is a pre-existing backlog (340 at v7.2.0), unchanged by this release —
  every string 7.2.7 adds or changes ships complete in all 46.
- Zendesk escalation, voice, avatar, and attachment upload remain untested on
  staging. Escalation is the one worth exercising before launch, because the
  consent notice promises it shares the conversation plus name and email.
- PostgreSQL has never been covered in this series on any site.

### Config change to make alongside this deploy

The FAQ rewrite is the configuration half of the retrievable-FAQ change and is
**not** shipped in code — `faq_content` is a site setting. The replacement text
is in `.drafts/faq_content-v7.2.7.txt`: 13 pairs, 2,643 chars, down from 17
pairs and 4,403. The four dropped pairs ("when does my course begin", "how long
is my course", "where are the lecture videos", "how do I turn in my
assignments") answer per-course questions with a site-wide answer that competes
with the correct one in the retrieved course content.

After changing `faq_content`, the index is stale by hash and the plugin reverts
to inline injection until the next run of the **Index course content** scheduled
task, which refreshes the FAQ alongside any course reindex. A manual reindex
from the RAG admin page does the same immediately.

### Verification

1094 tests passing (up 64), 5082 assertions, 0 failures. Validators 36/36. PHP
lint clean across 474 files. All 46 locales complete for every string this
release touches.

## Part 2: Key SOLA Features

Carried forward from v7.2.3. No feature changes. Admin settings added since
then: System prompt budget mode (7.2.4), quiz-lock scope (7.2.5), and a
settings-page warning when auto budget mode has no context window to derive
from (7.2.7). One new admin CLI, `audit_config_log_secrets.php` (7.2.4). The
budget auto-tuner is deprecated as of 7.2.6 and stands down unless the budget
mode is `fixed`.

## Part 3: Admin Walkthrough

### 1. Finish a quiz and immediately ask a question

Start an attempt on a quiz in a course, confirm the drawer is disabled and shows
the integrity notice, submit the attempt, then send a message in the same course.

**Expected:** it answers immediately. The lock lifts on submission, not when a
freshness window expires. Before this release it would keep refusing — and would
also refuse in every other course you opened.

### 2. Confirm the lock does not follow you between courses

With an attempt open in course A, open the assistant in course B.

**Expected:** course B works normally. Only course A is locked. If you want the
old site-wide behavior, Site administration → AI Course Assistant → *How far the
lock reaches* → **Every course**.

Worth knowing why the default changed: an abandoned attempt stays `inprogress`
forever, so under site-wide scope one forgotten quiz anywhere in a learner's
history disables the assistant in all their courses permanently.

### 3. Check that the input is disabled exactly when the server will refuse

While an attempt is open, open the drawer in that course.

**Expected:** the textarea and all six starter chips are disabled, and the notice
names the remedy — submit or close the attempt. There should be no state where
the box looks usable and the send is then refused.

### 4. Reload a conversation that had a failed turn

Open a course conversation with history.

**Expected:** zero occurrences of `core\`, `exception`, or `moodle_` anywhere in
the transcript. Old rows stored before 7.2.4 render the same learner-facing
notice as new ones.

### 5. Analytics with All courses selected

Site administration → Analytics, picker on **All courses**.

**Expected:** TOTAL STUDENTS carries a real number, at least as large as any
single course and at least as large as ACTIVE AI USERS. Note these two measure
different things: TOTAL STUDENTS is active enrolments, ACTIVE AI USERS is people
who actually used SOLA, so the gap between them is your adoption rate.

### 6. Read the privacy notice next to the audit log

Open the learner privacy notice, then the admin audit log.

**Expected:** the notice says SOLA keeps no record of its own of your name, and
that a name shown alongside SOLA data comes from your existing Moodle account.
That should read as consistent with the audit log showing full names.
