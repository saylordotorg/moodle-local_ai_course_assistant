# SOLA v7.8.9: Release Notes and Walkthrough

## Part 1: Release Notes (15 October 2026)

## v7.8.9 (15 October 2026): server faults count as failures, and one learner can't pause a provider

A review of the whole 7.8.8 change found six problems. This patch fixes them. Nothing here changes the database or adds a setting.

**A server fault is a failure, not a refusal.** In 7.8.8 a chat turn that stopped before any provider was chosen was filed as blocked unless its error code started with `chat:error`. A database error or a coding error while a turn was being prepared matched that rule, so the failed-reply alert could not see a site-wide outage of that kind. Now only the guards that stop a turn on purpose raise a dedicated refusal (`provider\chat_refused_exception`): the emergency pause, the quiz lock, the request rate limit and a spend cap with no failover. Those turns are stored as blocked. Everything else is a failure.

**A provider that refuses everything is paused.** A provider that rejects every request as malformed, for a reason the plugin hasn't learned (a region block, a parameter it doesn't know), never opened a circuit in 7.8.8, so every turn paid for a refused request, up to two retries and a fallback. Now six refusals in a row inside two minutes, with no success between, pause it for 15 minutes. No single learner can supply more than two of the six, so it takes at least three different learners, and one learner who can reliably get a 400 can't push the whole site onto the backup.

**Passing faults are counted over five minutes.** A rate limit, outage or timeout pauses a provider on the second failure in a row. That window was one minute. On a quiet site two failures a minute or two apart never counted together, so every learner waited out the provider's timeout. It's five minutes now.

**Smaller fixes.** The daily backup check resolves a site provider set to Auto the same way chat does. Before, a backup of the same provider with no model of its own was probed on the provider's default model instead of the site model. README and the developer notes lost three statements the review found the code didn't back up.

**Translations.** The Bambara and Wolof values of the 19 admin strings added in 7.8.8 are English again. A back-translation check, where each locale's strings were translated back to English without seeing the original, showed them losing the meaning, and a misleading admin string is worse than an English one. Igbo, Zulu, Yoruba, Oromo and Somali read mostly right with some odd words, and are waiting for a native-speaker review.

**Known limits.** A site with fewer than three active learners can't open the refusal pause. Each refused turn there still falls back to the backup for that request only. The backup check tests site-level settings only, so a course with its own provider isn't probed.

Plugin version `2026101500`, release `7.8.9`. Change: #326.

## Part 2: Walkthrough (about 2 minutes (admin))

Nothing a learner sees changes in this patch.

1. With the site provider set to Auto, run `php local/ai_course_assistant/admin/cli/verify_failover.php`. A backup that uses the same provider is probed on the site model, not the provider's default.
2. Switch Moodle to Bambara or Wolof and open the plugin's admin pages. The 7.8.8 admin text is English until a native speaker has reviewed it.
3. Upgrade from 7.8.8. No new tables, columns, settings, scheduled tasks or capabilities are registered.
