# SOLA v7.12.2: Release Notes and Walkthrough

## Part 1: Release Notes (19 October 2026)

## v7.12.2 (19 October 2026): the Moodle plugin reviewer's four findings, and admin text that matches the code

The Moodle plugin reviewer replied on CONTRIB-10574 on 19 October with four findings (issues #339 to #342). This release fixes all four, and fixes more than he named where our own audit found the same problem. It adds no setting, table or capability. It has two upgrade steps.

**An upgrade step read `$CFG` without declaring it (#339).** The step that gives each email opt-out an owner (2026100102) bound a null host id on every Moodle version, so it claimed nothing. The upgrade function now declares `$CFG`, and a new step (2026101902) runs the claim again for sites that already passed the old one. An opt-out is claimed only when exactly one live account holds the address.

**The Privacy API now declares every place learner data can go (#340, the approval blocker).** Before, `get_metadata()` named five destinations. It now also declares Soapbox recording storage, WhatsApp delivery, the embedding provider, the Redash analytics export, talking avatars, the widget CDN (when you set one), browser speech recognition and read-aloud, and the usability-testing form (which carries the learner's user id to the form's host), and it says that several features can use a different AI provider from chat. It also declares and exports the six user preferences the plugin sets (a new user-preference provider). Two payloads no longer carry the learner's user id: the Synthesia avatar request and the xAI Realtime token (the Worker never read it). A new test scans the PHP and browser code, so a new outbound call fails the build until it's declared or allowed with a reason. The text for Soapbox storage says plainly what happens when recordings are deleted and what doesn't remove them.

**A learner now gets only passages from activities they can see (#341).** The index is built as an administrator, so it held text from hidden and restricted activities. Retrieval now checks each passage against the learner it's for: hidden activities, hidden sections, dates, group and grade restrictions, and activities that no longer exist are dropped, in both chat paths. Teachers keep their drafts. A learner who can't access the course they're chatting in gets only the site FAQ. The filter runs on the final top results and doesn't refill, so a turn can get fewer than five passages, and a course whose best matches are all hidden gives a learner fewer. The summaries of hidden and restricted sections and subsections are left out of the course-level passage, the course outline in the prompt lists only what the learner can see, and an assignment description that shows only from its submission date isn't indexed before then. Upgrade step 2026101903 deletes the old course-level passages; the nightly index rebuilds them (until 02:00, or a reindex on the RAG admin page, learners lose the course and section summaries from answers).

**Old settings links no longer end in a coding error (#342).** Opening an old settings address such as `admin/settings.php?section=local_ai_course_assistant_general` used to redirect while Moodle 5.x was drawing the page header, which is a coding error. The old pages now show a short notice with a link to the new page and take you there automatically.

**Admin text.** Four descriptions now say what the code does: the site cap (`spend_cap_site`) isn't a site total, the failover list uses only its first chat line when a cap trips, the Soapbox notices mention the PresenterAI importer and the guards added in 7.12.1, and the chat, retrieval and analytics cap texts (the analytics cap isn't enforced). The 45 translations of those eight strings were out of date, so they're removed and these strings show in English until retranslated.

**Known limits.** Hidden-activity text still goes to the Voyage reranker before the filter (it was already embedded by the same vendor at index time). A section hidden after indexing stays in the course-level passage until the nightly run. `voice_provider:audio` still reads "for transcription" in the 45 translations. The reminder and digest emails to addresses an administrator types aren't a Moodle-user destination and aren't declared separately.

Plugin version `2026101903`, release `7.12.2`.

## Part 2: Walkthrough (about 4 minutes (admin))

1. After upgrading, open Site administration, Plugins, Privacy and policies, Data registry, and find AI Course Assistant: the external destinations list is longer, and each says what is sent and when.
2. As an administrator open `admin/settings.php?section=local_ai_course_assistant_general` (an old address). You should see "This settings page has moved to Essentials" and land on Essentials with no error.
3. In a course, hide an activity that mentions a distinctive word and ask SOLA about it as a student. The answer should not use or cite it. As a teacher, ask again: it can.
4. Look at the RAG admin page for a course: the course-level passage is rebuilt after the next nightly index (or press Reindex).
5. Upgrade from 7.12.1 runs two steps (2026101902, 2026101903) and registers no new tables, settings, capabilities or scheduled tasks.
