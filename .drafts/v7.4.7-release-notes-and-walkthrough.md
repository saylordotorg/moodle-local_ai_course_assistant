# SOLA v7.4.7 — Release Notes, Feature Summary, and 20-minute Admin Walkthrough

## Part 1: Release Notes (14 September 2026)

**The assistant stops leaking its own protocol tokens to learners, and 82 strings that shipped as English in all 45 translations are now actually translated.**

- **Protocol tokens no longer reach learners.** The system prompt emits control markers that `chat.js` is meant to strip before rendering. Some reached the transcript instead. They are now stripped on the server side as well, so a marker cannot survive a client that missed it. The course map is also kept whole rather than being cut mid-structure when the prompt budget was tight.
- **82 teacher- and learner-facing strings are translated into all 45 languages.** These keys were *present* in every locale file while still holding the English text, so every completeness check passed and the UI still rendered English. Affects the course settings page, the instructor dashboard, essay feedback, and the Python sandbox. Admin-only settings copy is deliberately unchanged — see below.
- **A new gate makes that class of bug fail loudly.** `lang_completeness_test` previously asked only whether a key *existed* in each locale. It now also asks whether every locale is holding the English value, which is what "translated" quietly failed to mean for those 82 keys.
- **An unknown objectives import source is rejected instead of failing on insert.** `objs.source` is `char(20) NOT NULL` and was the only field in the insert without a length clamp, so an over-long posted value was a database error rather than a truncation. Admin-only and sesskey-gated, so low severity.
- **`local_outcomemap` bridge audited, no change needed.** The absent-plugin path has four independent guards and cannot fatal on a site without the companion plugin. Two known gaps are recorded below rather than fixed.

### Known gaps, recorded deliberately

- The **present-plugin** path of `outcomemap_bridge` has no test coverage: every test skips when `local_outcomemap` is installed, so the DTO field names are verified only against the deployed plugin by inspection.
- **Re-importing outcomes duplicates rows.** Nothing looks up `external_ref` before inserting, yet that field deliberately carries the outcome *version* uuid — so the intended response to an upstream wording edit doubles the rows instead of superseding them.

### Not in this release

The ~250 admin-only strings behind `moodle/site:config` remain untranslated on purpose. That copy is dense operational text (token budgets, SSRF pinning, rerank candidate pools) whose English an operator is already following in the runbooks; translating it would drift against those docs for the smallest and most English-fluent audience. They stay tracked in `IDENTICAL_TO_ENGLISH_BACKLOG`.

### Testing

- Full PHPUnit suite: **1639 tests, 7220 assertions, 1 skipped, 0 failures**.
- Static validator suite: **36 passed, 0 failed, 0 skipped**.
- PHP lint: **544 tracked files, 0 failures**.
- CI: all 10 matrix jobs green (PHP 8.1/8.2/8.3 × Moodle 4.5/5.0/5.1 × pgsql/mariadb).
- i18n: 3690 translated strings machine-checked — every `{$a}` placeholder and every `[[brand token]]` byte-identical to source, no key missing, no key English in all 45 locales.
- Both new guards proven to fail without their fix, against a disposable copy rather than the tracked tree.
- Jailbreak suite: see the run recorded at release time. Gate is 0 FAIL and 0 ERROR, not a pass rate — on the production `gemini-2.5-flash` the remainder score as REVIEW, which only means no pass-indicator regex matched.

Plugin version `2026091400`, release `7.4.7`.

## Part 3: Admin Walkthrough

### 1. Finish a quiz and immediately ask a question

Start an attempt on a quiz in a course, confirm the drawer is disabled and shows
the integrity notice, submit the attempt, then send a message in the same course.

**Expected:** it answers immediately. The lock lifts on submission, not when a
freshness window expires. Before this release it would keep refusing — and would
also refuse in every other course you opened.

### 2. Confirm the lock does not follow you between courses

With an attempt open in course A, open the assistant in course B.

**Expected:** course B works normally. Only course A is locked. If you want the
old site-wide behavior, Site administration → AI Course Assistant → *How far the
lock reaches* → **Every course**.

Worth knowing why the default changed: an abandoned attempt stays `inprogress`
forever, so under site-wide scope one forgotten quiz anywhere in a learner's
history disables the assistant in all their courses permanently.

### 3. Check that the input is disabled exactly when the server will refuse

While an attempt is open, open the drawer in that course.

**Expected:** the textarea and all six starter chips are disabled, and the notice
names the remedy — submit or close the attempt. There should be no state where
the box looks usable and the send is then refused.

### 4. Reload a conversation that had a failed turn

Open a course conversation with history.

**Expected:** zero occurrences of `core\`, `exception`, or `moodle_` anywhere in
the transcript. Old rows stored before 7.2.4 render the same learner-facing
notice as new ones.

### 5. Analytics with All courses selected

Site administration → Analytics, picker on **All courses**.

**Expected:** TOTAL ENROLLED carries a real number, at least as large as any
single course and at least as large as ACTIVE AI USERS. The two measure
different things: TOTAL ENROLLED is active enrollments, ACTIVE AI USERS is
people who actually used SOLA, so the gap between them is your adoption rate.
MSGS / ACTIVE USER divides by the second of those, not the first — which is why
both tiles were renamed in this release.

### 6. Read the privacy notice next to the audit log

Open the learner privacy notice, then the admin audit log.

**Expected:** the notice says SOLA keeps no record of its own of your name, and
that a name shown alongside SOLA data comes from your existing Moodle account.
That should read as consistent with the audit log showing full names.
