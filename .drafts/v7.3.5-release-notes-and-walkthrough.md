# SOLA v7.3.5 — Release Notes, Feature Summary, and 20-minute Admin Walkthrough

## Part 1: Release Notes (6 September 2026)

The Moodle plugin-directory review response: all six open reviewer issues
(#200-#205) addressed and closed.

- **Templates + Output API transition complete (#201).** The last six
  echo-rendered pages — objectives admin, demo admin, Soapbox presenter,
  transcript report, outcomes report, and starter settings — are now Mustache
  templates rendered through the Output API. Every plugin page now renders
  via render_from_template. The final inline scripts moved into AMD
  (starter reset confirms into starter_admin).
- **378-key i18n extraction (#205).** A full sweep found the analytics
  dashboard, token analytics, the privacy notice, the widget help panel, the
  mobile-app UI, and a dozen smaller surfaces still hardcoded in English.
  All 378 strings extracted to lang keys and translated into all 45
  non-English locales (46/46 completeness). White-label branding tokens now
  reach every one of those surfaces. Bug found along the way: the plugin had
  no component-level 'error' lang string, so several moodle_exception
  messages were silently demoted to debug info — now visible.
- **Boilerplate markers (#202)**: @package/@copyright/@license added to the
  two templates the reviewer flagged.
- **Backup/restore (#200)**, the **cross-DB return-rate SQL (#203)**, and the
  **self-updater removal (#204)** shipped in earlier 7.x releases; the
  remaining gap (one undocumented backup exclusion) is documented and the
  14-test backup/restore roundtrip re-verified.

### Three more defects found while doing the above

- **Three malformed placeholders shipped to learners.** Bambara and Somali had
  `{$a>` and Tagalog `{$a->title)` where a closing brace belonged, so those
  learners saw the raw fragment instead of a number or a title -- "Mɔgɔ {$a>
  bɛ kalan na sisan." Nobody smoke-tests in Bambara, and the completeness
  test only checks that a key EXISTS, so nothing caught it.
- **265 shadowed lang-key definitions across 36 locales.** PHP keeps the last
  assignment, so a duplicate is not an error -- it is a trap. 221 of the 265
  held text that DIFFERED from the winning copy (mostly pre-tokenization
  literals like "KI-Tutor" left behind when v6.8.0 appended rebranded
  overrides rather than editing in place). Anyone who found one by grep and
  corrected it would have seen no change on screen. All 265 removed, with a
  proof that the effective last-wins value map is byte-identical before and
  after.
- **127 translations silently opt out of white-label rebranding** by dropping
  the `[[brand token]]` the English string carries, so on a rebranded install
  they show the wrong product name or none. These are stale translations of
  English strings that predated the v6.8.0 tokenization. Frozen as documented
  debt that can only shrink, not fixed in this release.

### A third guard

`tests/lang_placeholder_integrity_test.php` enforces what the completeness
test cannot: that `{$a}` placeholders survive translation exactly (no debt
list -- broken interpolation is visible breakage), that `[[brand tokens]]`
survive with the 127 known gaps frozen in a fixture that may only shrink, and
that no key is defined twice in a lang file. Watched failing on the real
Bambara defect before being trusted.

### Testing

- 1,169 tests, 0 failures. Validators 36/36. i18n completeness 46/46.
  Placeholder integrity clean. Page smoke 23/23.

Plugin version `2026090900`, release `7.3.5`.

## Part 3: Admin Walkthrough

### 1. Finish a quiz and immediately ask a question

Start an attempt on a quiz in a course, confirm the drawer is disabled and shows
the integrity notice, submit the attempt, then send a message in the same course.

**Expected:** it answers immediately. The lock lifts on submission, not when a
freshness window expires. Before this release it would keep refusing — and would
also refuse in every other course you opened.

### 2. Confirm the lock does not follow you between courses

With an attempt open in course A, open the assistant in course B.

**Expected:** course B works normally. Only course A is locked. If you want the
old site-wide behavior, Site administration → AI Course Assistant → *How far the
lock reaches* → **Every course**.

Worth knowing why the default changed: an abandoned attempt stays `inprogress`
forever, so under site-wide scope one forgotten quiz anywhere in a learner's
history disables the assistant in all their courses permanently.

### 3. Check that the input is disabled exactly when the server will refuse

While an attempt is open, open the drawer in that course.

**Expected:** the textarea and all six starter chips are disabled, and the notice
names the remedy — submit or close the attempt. There should be no state where
the box looks usable and the send is then refused.

### 4. Reload a conversation that had a failed turn

Open a course conversation with history.

**Expected:** zero occurrences of `core\`, `exception`, or `moodle_` anywhere in
the transcript. Old rows stored before 7.2.4 render the same learner-facing
notice as new ones.

### 5. Analytics with All courses selected

Site administration → Analytics, picker on **All courses**.

**Expected:** TOTAL ENROLLED carries a real number, at least as large as any
single course and at least as large as ACTIVE AI USERS. The two measure
different things: TOTAL ENROLLED is active enrollments, ACTIVE AI USERS is
people who actually used SOLA, so the gap between them is your adoption rate.
MSGS / ACTIVE USER divides by the second of those, not the first — which is why
both tiles were renamed in this release.

### 6. Read the privacy notice next to the audit log

Open the learner privacy notice, then the admin audit log.

**Expected:** the notice says SOLA keeps no record of its own of your name, and
that a name shown alongside SOLA data comes from your existing Moodle account.
That should read as consistent with the audit log showing full names.
