# SOLA v8.3.1: Release Notes, Feature Summary, and Admin Walkthrough

## Part 1: Release Notes (22 November 2026)

## v8.3.1 (22 November 2026): voice stops listening when nobody speaks, and no raw markers in the voice transcript

**Why this release exists.** Two things found while testing 8.3.0 on dev.

1. **An open microphone costs money.** Live voice is billed for as long as a session is open, and the old Gemini Live silence limit was 90 seconds. Every voice mode now stops listening after a short silence and the learner taps **Resume** to carry on.
2. **The regular voice mode showed raw markers.** The assistant's replies in voice mode carried the citation marker `[[c:1]]` and the source tag `[SOURCE:activity:522]` inline, and the same text was sent to text to speech, so a marker could also be read aloud. The chat panel turns those markers into its source pill; the voice mode never did.

**Stop listening after silence.**

| Voice mode | Stops after | Setting |
|---|---|---|
| Gemini Live (two-way, with the avatar) | 5 seconds (was 90) | Stop listening in Gemini Live after silence (`gemini_live_idle_seconds`), 3 to 600 |
| OpenAI and xAI realtime, and the regular voice mode that listens, thinks and speaks | 10 seconds (new) | Stop listening in other voice modes after silence (`voice_idle_seconds`), 5 to 600 |

- **What counts as silence.** Time in which the learner has not spoken. The count does not run while the model is answering or about to answer (a long answer can't use it up) and starts again when the model stops talking. A learner's speech, or a typed chip, restarts it. A model that never answers can hold a Live session open for at most 20 seconds before the count starts.
- **What happens when it trips.** The microphone closes, the live session ends (so nothing more is billed), the session's length and tokens are reported as usual, and the overlay shows "Stopped listening to save credits. Tap Resume when you are ready." with a **Resume** button (and End conversation). Resume opens the microphone again. For the live modes that is a new session: it asks the server for a new token, so it counts toward the per-session cap and the learner's daily Gemini Live allowance, and it does not repeat the opening prompt. The regular voice mode keeps its connection, so its Resume only reopens the microphone.
- **Where the words live.** Language strings `voice:idle_stopped`, `voice:resume` and `voice:resume_aria` (the button's accessible name), carried to the widget in data attributes. English first; other languages fall back to English until translated.
- **A real bug fixed on the way.** The Live silence clock used to run from the last audio chunk's arrival, not from the end of playback, so a limit as short as 5 seconds would have ended the session the moment a long answer finished. The count now starts when the model stops.
- **What the server holds regardless of the browser.** The silence limit is enforced in the learner's browser, because a live session talks to the provider directly. What the server enforces however the browser behaves: the session cap (the token expires), the daily allowance, and the spend caps. A browser that ignores the silence limit can keep one session open until its cap, no longer.

**Upgrade notes: existing sites.**

- **Gemini Live silence limit.** A site whose limit is exactly **90** (the old default) moves to **5** on upgrade. Moodle writes a setting's default to the database the first time the settings page is saved, so 90 almost always means "never changed". Any other value (30, 120, 15, anything an admin typed) is kept as it is. A site that wants 90 sets it again. The upgrade prints a line when it changes the value. The lower bound moved from 15 to 3 seconds.
- **The new other-modes limit** is 10 seconds on every site, because it did not exist before. It applies to OpenAI and xAI realtime and to the regular voice mode, which used to keep listening indefinitely.
- No schema change. Purge caches after upgrading so browsers load the new JavaScript.

**No more raw markers.** The voice transcript now drops `[[c:N]]` citation markers and `[SOURCE:...]` tags (any of the forms the model writes: `[SOURCE:activity:522]`, `[[SOURCE:...]]`, free-form labels such as `[SOURCE:Unit 1: Computer Programming]`), wherever the reply happens to be split into chunks. A marker that has only partly arrived is held back, so a bare `[` never flashes. The text sent to text to speech is cleaned the same way, and a full stop or colon inside a half-arrived marker can no longer end a spoken sentence. The Gemini Live and OpenAI realtime transcripts get the same filter. The voice overlay has no source pill, so the sources are not shown there; the chat panel is unchanged.

**Not verified.** Everything below needs a person with a microphone on dev.sylr.org, because the checks here have no real audio:

- the 5 second and 10 second limits against a real microphone and real provider audio;
- that the Resume button restarts listening on a phone (iOS needs the new audio context to be made inside the tap; it is);
- that a learner who is thinking for longer than 5 seconds finds the limit acceptable (a longer value is one setting away).

### Testing

- New `tests/voice_idle_test.php` (7 tests): the defaults, the bounds, junk input, the upgrade moving exactly 90 and nothing else, the upgrade being safe to repeat and safe when the setting was never saved, and the wiring.
- New `tests/js/voice-idle-check.js` (against `amd/src` AND the built `amd/build`): a fake clock drives whole sessions of `gemini_live.js`, `realtime.js` and `voice.js`. It checks the 5 and 10 second defaults and a configured limit, one stop and one usage report, speech and a pending answer holding the count off, the count starting when playback ends (planted defect: removing that hold-off makes it fail), Resume starting a new session, and that no marker survives at any split point of a reply in any of the three modes (planted defect: removing the marker filter makes it fail). It also checks the wiring in `chat.js`, `ui.js` and the template, source and build.
- Existing tests updated for the new defaults: `voice_gemini_live_test`, `gemini_live_token_endpoint_test`.

Plugin version `2026112200`, release `8.3.1`.

## Part 3: Admin Walkthrough Script: keeping voice costs down (about 2 minutes, conversational)

### 1. Why (about 20 seconds)

"An open microphone costs money, especially in live voice. From 8.3.1 every voice mode stops listening when nobody speaks, and the learner taps Resume to carry on."

### 2. The two settings (about 50 seconds)

Open Site administration, Plugins, Local plugins, then the assistant's settings, and find the voice section. "Gemini Live stops after 5 seconds of silence by default. Every other voice mode stops after 10. Both are in seconds, and both are one setting." Show the two fields. "If your learners need longer to think, raise them."

### 3. What a learner sees (about 40 seconds)

Start a voice conversation as a student, stay silent, and show the message "Stopped listening to save credits. Tap Resume when you are ready." Tap Resume and speak. "Live voice starts a new session when you resume, so it counts toward the daily Gemini Live allowance."

### 4. Upgrading (about 10 seconds)

"A site that still had the old 90 second default moves to 5. If you had chosen a different number, it stays."
