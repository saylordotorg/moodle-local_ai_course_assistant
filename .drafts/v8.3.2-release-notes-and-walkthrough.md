v8.3.2 (23 November 2026): Gemini Live starts again (the token request had the wrong shape)

**Why this release exists.** On dev, Gemini Live always fell back to the regular voice mode ("Live voice isn't available right now, so this conversation uses the regular voice mode."), so the learner could talk but the answer came from the regular mode, not Live.

**Cause.** To keep the site's Gemini key out of the browser, SOLA mints a short-lived, single-use Live token on the server. The request body nested the session settings one level too deep (`bidiGenerateContentSetup.setup`). Google refuses that with HTTP 400 (`Unknown name "setup" at 'auth_token.bidi_generate_content_setup'`), so every Live start failed and the browser fell back. The body shape had been written from documentation and never checked against a live call.

**Fix.** The settings now sit directly under `bidiGenerateContentSetup`, with the same locked fields as before. Checked against Google on 2026-11-23: the old shape returns HTTP 400, the new shape returns HTTP 200 and a token.

**Upgrade notes.** No setting changes, no schema change. Purge caches after upgrading. Sites that never turned Gemini Live on are unaffected.

### Testing

- `tests/voice_gemini_live_test.php` and `tests/gemini_live_token_endpoint_test.php` now assert there is no nested `setup` key (the old shape makes them fail).
- `tests/voice_idle_test.php` no longer pins the exact build number; it asserts the build is at least the one that carries the upgrade step.
- New `tests/live/voice-idle-live-check.js`: a real-browser check of the silence limit and Resume against a live site (needs a signed-in demo-studio browser; not part of CI).
- Not covered by automated tests: a real two-way Live conversation with real audio. Try it on dev.
