# SOLA v7.12.1: Release Notes and Walkthrough

## Part 1: Release Notes (19 October 2026)

## v7.12.1 (19 October 2026): a spend cap now fails over to the backup's own model, and Soapbox cleanup leaves what PresenterAI's importer holds

This patch fixes one bug in how a spend cap hands chat to the backup provider, and adds a guard that PresenterAI 0.5.0's Soapbox importer needs. It adds no setting, table, column, capability or scheduled task.

**A spend cap now fails over with the backup's own model.** When a cap tripped and a backup was configured, chat moved to the backup's provider and key but kept the main model name and the base URL. An OpenAI backup behind a Gemini main was asked for `gemini-2.5-flash` and answered HTTP 404. The per-call backup path got this fix in 7.2.8. The cap path never did. Now the backup's own model and base URL go out. A backup row with no model of its own uses its provider's default model. A backup on the same provider as the main, with no model of its own, keeps the model the call was already using, which is a course's own model when the course sets one.

**Soapbox cleanup skips recordings PresenterAI has taken over.** The nightly Soapbox cleanup now asks PresenterAI's migration map which recordings it holds, and skips them: the recording row, its video, slide deck and frame sheet stay as they are, and a held recording still counts toward its learner's newest-attempts window so other attempts are pruned exactly as before. The body-language note a vision model wrote about a learner is still removed when a held recording would have been retired, because the 7.5.1 promise is that it goes with the video. The task writes one `soapbox_cleanup_interlock` audit row per run with the number of recordings it skipped. If the lookup itself fails, the task writes one `soapbox_cleanup_interlock_failed` row (the error class only), stops, and fails, so nothing is deleted on a guess. On a site without PresenterAI nothing changes. PresenterAI 0.5.0's importer refuses to run unless this interlock is present.

**Known limits.** The first three were true before this release and still are:
- A site-level base URL (`apibaseurl`) still reaches a backup row that has none of its own, on both failover paths. It matters only on a site that sends its main provider through a gateway URL. Dev and alpha have none.
- With per-call failover on and a cap tripped, the backup is tried first and then listed again. The second try only runs if the first fails.
- `spend_cap_site` is not a site total. It caps one course's chat spend, or site-wide voice spend, or site-wide retrieval spend. Setting `spend_cap_chat` overrides the per-course default. `spend_cap_analytics` is not enforced anywhere.
- A tripped cap with a backup configured now answers on the backup vendor and spends there, uncapped, until the period ends. This covers every AI feature in a capped course that builds its provider the standard way: chat, quiz generation, essay scoring, the mastery classifier, premium escalation and the Soapbox slide and gesture vision calls. Before, with per-call failover off, a backup from another vendor failed, which acted as an accidental stop.

**What the interlock does not cover.** A bucket lifecycle rule on the Soapbox prefix still deletes held objects whatever the interlock says, so keep its age longer than PresenterAI's retention. A learner who deletes their Soapbox data from SOLA's own settings page does not reach PresenterAI's copy. Moodle's privacy tools cover both, and so does PresenterAI's own delete. Deleting a whole Soapbox assignment is refused while PresenterAI holds any of its recordings, and deleting a course still removes everything.

Plugin version `2026101901`, release `7.12.1`. Change: #338.

## Part 2: Walkthrough (about 3 minutes (admin))

Nothing a learner sees changes unless a spend cap trips.

1. On a test course, set a $0.01 course cap in the course settings under More options, send one chat, and watch the answer come from the backup provider with the backup's own model (the usage log shows the backup's provider and model). Clear the cap afterward.
2. Open Site administration, Reports, Logs, or the audit log page, and filter for `soapbox_cleanup_interlock`. After the nightly task runs on a site with PresenterAI 0.5.0 and imported recordings, the row's count is the number of recordings it left alone.
3. Upgrade from 7.12.0. No new tables, columns, settings, scheduled tasks or capabilities are registered.
