v7.4.7 supersedes v7.4.1 through v7.4.6, none of which were submitted here, so these notes cover the whole 7.4 line.

NEW IN v7.4.7

- The assistant no longer shows learners its own internal markers. The system prompt emits control tokens that the browser strips before rendering an answer. Some were surviving into the transcript, so a learner could see internal protocol syntax mid-reply. Stripping now also happens server-side, so a marker cannot get through on a path where the client-side strip was missed. Relatedly, under a tight prompt budget the course structure block could be truncated mid-way, handing the model a half-described course; it is now kept whole or omitted entirely.

- 82 interface strings that displayed in English to every learner, in every language, are now translated into all 45 non-English locales. The failure is worth describing precisely because it defeated the check already in place: the keys were present in every translation file while still holding the English text, so a completeness check that asked only whether a key exists in every locale passed, and the interface still rendered English. The affected surfaces are the course settings page, the instructor dashboard, essay feedback and the Python sandbox. A new automated check now fails the build when a string is present in every locale but still holding the English value.

- The batch was produced per-locale against each locale's existing file so register and terminology match what already ships, then reviewed against already-translated sibling keys. That review produced 474 corrections, mostly terminology that had drifted from an existing twin string. All 3,690 translated strings were then machine-checked: every placeholder and every branding token byte-identical to source, no key missing, and no key left as English across all locales.

- Administrator-only strings are deliberately not translated and remain tracked as known debt. That copy is dense operational text, whose English an operator is already following in the written runbooks; translating it would drift against those documents for the smallest and most English-fluent audience.

- An invalid learning-objectives import is now rejected rather than failing at the database. One field in that insert had no length limit applied where every neighboring field did, so an over-long value produced a database error instead of being truncated, and a short unrecognized value inserted successfully then rendered as a missing-string placeholder. The valid set is now declared in one place and enforced at the form. Administrator-only and form-token protected, so severity is low.

- The optional outcomes-mapping integration was audited and needed no change. Its absent-plugin path has four independent guards and cannot fatal on a site without the companion plugin, which is the path the test suite exercises.

EARLIER IN THE 7.4 LINE (v7.4.0 through v7.4.6)

- Retrieval default corrected. v7.4.0 described asymmetric query and document embedding as dropped after failing to reproduce. That conflated two different things sharing a name: pairing a larger document model than query model genuinely did not reproduce, but sending the vendor its intended input_type hint is a different mechanism and does reproduce. The shipped default sent the same projection hint when indexing and when searching, measuring 42.6% Recall@3 where the index it was meant to replace measured 52.8% - so a site could pay to re-embed its whole corpus and retrieve worse than before. The vendor's intended mode measures 66.7% on the same stored vectors. Evidence is 816 anchored fixtures across 13 courses against a 17,257-chunk index. Switching requires no re-index, since only the query-side projection changes. Existing sites keep their stored value, so this fixes new installations; the notes carry a one-line recovery action for sites already affected. A reranker had been masking the problem, so an affected site could not have detected it from its own numbers.

- Spend accounting was reading a floor rather than a bill. Five components made real billable model calls that nothing recorded, reasoning tokens were never read although both major vendors report them, and three further endpoints persisted no usage. One month showed $3.96 estimated against an $11.13 invoice. Reasoning tokens are now stored exactly as reported and never folded into completion tokens, because one vendor includes them and another does not. The coverage check is now structural: it scans the source for every usage type, and each must either appear in the billing predicate or be listed as not billable with a stated reason. Confirmed by planting a sixth unlogged writer and watching the build fail. Expect reported spend to rise after upgrading with no change in actual spend.

- Learning objectives can come from curated data instead of guesswork. The previous approach scraped course content looking for something bullet-shaped, which in practice yielded course names rather than objectives. Where the optional outcomes-mapping plugin is installed, approved versioned outcome statements are read from its public API first, returning before the content walk starts. Sites without that plugin behave exactly as before. Four call sites that formatted module content without first rewriting plugin file URLs are also fixed.

- Scheduled analytics moved onto the vendor batch API at half price for input and output, which suits a slot that is offline by definition. Batched calls carry a distinct model prefix so the discount reaches pricing. The model registry now tracks end of life, recording which vendor surface a retirement date applies to. Embedding calls gained retry: embeddings were the only provider path with no backoff, so a single rate-limit response ended an all-or-nothing indexing run.

- Smaller fixes: a restored course could carry a model identifier the site cannot serve, rejecting every chat turn in that course; streaming provider errors discarded the response body on any 4xx; a byte-wise prompt truncation could split a multibyte character, breaking JSON encoding and preventing the closing untrusted-content marker from being re-added, which made it a prompt-injection surface as well as a correctness bug. Speaking assignments can sit in a course section as an ordinary activity. Object storage can be round-trip tested from the self-test page.

UPGRADING

Additive. Four upgrade steps run from v7.4.1: one nullable column on the messages table, one new table created empty, two nullable columns on the model registry table, and one metadata-only step. v7.4.7 itself adds no upgrade step. Nothing is dropped, renamed or rewritten, and no existing row is modified. A rehearsed upgrade produced a database identical to a fresh installation across all tables, columns and index rows, with Moodle's own schema checker passing on both.

QUALITY GATE

1,639 automated tests with no failures, 7,220 assertions. Static validators 36 of 36. Continuous integration across PHP 8.1 to 8.3 with MariaDB and PostgreSQL on Moodle 4.5, 5.0 and 5.1 - ten matrix jobs, all green. A prompt-injection suite runs against a live model: 28 pass, 0 fail, 0 error. The plugin ships 46 locales, and a translation-parity test fails the build when a new English string appears without translations unless explicitly staged as known debt.
