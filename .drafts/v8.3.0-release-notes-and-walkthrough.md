# SOLA v8.3.0: Release Notes, Feature Summary, and Admin Walkthrough

## Part 1: Release Notes (21 November 2026)

## v8.3.0 (21 November 2026): OpenAI retires its speech models; SOLA stops calling them on time

**Why this release exists.** OpenAI's deprecation notices (as fetched by the site owner on 21 November 2026) shut down the models SOLA's voice defaults use:

| Model | Used by SOLA for | Shuts down | Named replacement | What SOLA does |
|---|---|---|---|---|
| `tts-1`, `tts-1-hd`, `gpt-4o-mini-tts` | Read aloud (text to speech) | 6 January 2027 | `gpt-realtime-2.1-mini` | **No automatic successor.** That model is a Realtime (WebSocket) model, not a drop-in for the speech endpoint SOLA calls. From the date, an OpenAI text to speech row is passed over for the next voice row that can speak (a Gemini row). |
| `whisper-1`, `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, `gpt-4o-transcribe-diarize` | Microphone transcription | 26 February 2027 | `gpt-transcribe` or `gpt-live-transcribe` | From the date, calls to api.openai.com send `gpt-transcribe` (same endpoint, same upload). |
| `gpt-4o-mini-transcribe-2025-03-20` | (only if an admin names it) | 20 January 2027 | `gpt-4o-mini-transcribe-2025-12-15` | Moves to the named snapshot. |

Until those dates nothing changes: the same models are sent as in 8.2.0.

**Text to speech.** The catalog marks the three OpenAI speech models as retiring with no successor. From 6 January 2027 `voice_registry::resolve()` never returns a row whose model has been shut down: the chosen row gives way to the next row in **Voice providers** that can speak, in table order. With a Gemini row in the table, read aloud keeps working on Gemini. With none, the speak button gets a clear error naming the model, the date and the setting to change (**Voice providers**, then **Active TTS provider**), and the same line goes to the server error log. The old single-key setup (no rows, an OpenAI key) stops the same way. The retired model is never sent.

**Speech to text.** Transcription asks the registry for its model at call time (`voice_registry::stt_model()`), in `transcribe.php`, `soapbox_transcribe.php` and the Soapbox scorer. Only a row on `https://api.openai.com` is subject to the catalog: `whisper-1` until 25 February 2027, `gpt-transcribe` from 26 February. The request shape is unchanged (multipart, `file`, `model`, optional `language`).

**The self-hosted trap.** A self-hosted Whisper server uses the name `whisper-1` for its own model, and most send it by default. SOLA never remaps a model name for the self-hosted server, or for any endpoint that isn't exactly `https://api.openai.com` (another host, plain http, another port, user info). A test pins this, including a self-hosted URL that points at api.openai.com.

**A new STT model column.** Voice provider rows gain an optional eighth column, **STT model**, for an OpenAI row (blank: the catalog default). A row stored without it reads as before. The self-hosted server keeps its own **Selfhosted STT model** setting.

**The daily voice model watch** now also watches hosted speech to text (unless the self-hosted server takes every transcription). It warns 45 days ahead, as before. For OpenAI text to speech, the warning (from 22 November 2026) and the line after the shutdown say there is no replacement and recommend adding a Gemini text to speech row, naming `gemini-3.8-flash-lite-tts` as the cheaper Gemini model.

**Admin guidance.** The **Voice providers** description now says that OpenAI retires its text-to-speech models on 6 January 2027 and recommends adding a Gemini row (English only).

**Clock.** `voice_registry` reads Moodle's clock (`\core\di` `\core\clock`), so tests freeze it with `mock_clock_with_frozen()` instead of depending on today's date.

**Fixed: four tests broken since 8.1.0.** Three failed-save tests used a `gemini` voice row as "a provider the table doesn't know", which stopped being true when 8.1.0 added Gemini, so there was no failed save to check; they now use `elevenlabs`. The `tts.php` "200 that isn't audio" check pinned the inline guard 8.1.0 moved into `tts_request::extract_audio()`; it now pins the call, its 502 and exit, and the function's behavior. These failed identically on the 8.1.0 commit and passed on main (8.0.0) in the same private Moodle copy, so they were not an environment artifact.

**Upgrade notes.** No schema change and no upgrade step. Seven new strings, English only (`providerkeys:col_sttmodel`, `providerkeys:err_stt_model`, `voice:error_tts_retired`, four `voicemodels:line_*_nosuccessor`); `settings:voice_providers_desc` and `voicemodels:mail_watch_body` changed (both already English only). No JavaScript change.

### What the owner needs to do before 6 January 2027

1. On each site that reads answers aloud with OpenAI (dev, alpha, and any production site on 8.x): **Site administration > Plugins > Local plugins > AI Course Assistant > Advanced > Prompt, voice and display > Voice providers**.
2. Press **Add**, choose **Google Gemini**, paste a Gemini API key, label it (for example `gemini-tts`), TTS voice blank (Kore) or one of Kore, Charon, Puck, Zephyr, Aoede, Sulafat, Achird, Iapetus, Schedar, Erinome, and TTS model `gemini-3.8-flash-lite-tts` (the cheaper one; blank means `gemini-3.8-flash-tts`). Save.
3. Set **Active TTS provider** to that label. Save. (Optional but cleaner than relying on the automatic pass-over: with the OpenAI row still chosen, SOLA moves to the Gemini row on its own from 6 January, as long as the Gemini row is in the table.)
4. Open a course as a student and press the speaker button on an answer. It should play (Gemini returns WAV).
5. Speech to text needs no action: hosted OpenAI rows move to `gpt-transcribe` on 26 February 2027. A self-hosted Whisper server is not affected.
6. Production sites on 7.5.7 are not covered by any of this. 7.5.7 hard-codes `tts-1` and `whisper-1`; read aloud there stops working on 6 January 2027 and OpenAI transcription on 26 February 2027 unless prod moves to 8.3.0 or later (Catalyst) or voice is switched to another provider by hand.

### Not verified

- **No call to OpenAI was made.** That `gpt-transcribe` accepts the same multipart request on `/v1/audio/transcriptions` and answers `{"text": ...}` is assumed from OpenAI naming it as the replacement and from the dev key listing it; the switch is behind the catalog date, so nothing changes until 26 February 2027. Check it on dev before then (one recording through the mic button with the row's **STT model** set to `gpt-transcribe`).
- No OpenAI text to speech drop-in was found; `gpt-realtime-2.1-mini` was not tried for speech.
- `gpt-4o-mini-transcribe-2025-12-15` is listed as current; the notice did not give it a date.
- **Pricing:** `gpt-transcribe` has no rate-card entry in this branch (pricing files are another branch's). From 26 February 2027 transcription rows will carry that model name; add its price before then or the price-drift check will report it as unpriced.
- **Realtime voice transcript:** `amd/src/realtime.js` asks OpenAI Realtime for `transcription: {model: 'whisper-1'}` for the live transcript. That is the browser, not this endpoint, and was left alone (no JS change in this release). It needs its own change before 26 February 2027.

## Part 2: Key SOLA Features

Unchanged from 8.2.0 except voice:

- **Voice.** Read aloud through OpenAI (until 6 January 2027), xAI or Gemini text to speech; microphone transcription through OpenAI (whisper-1, then gpt-transcribe from 26 February 2027), xAI or a self-hosted Whisper server; live voice through OpenAI Realtime or Gemini Live. A catalog of voice models with shutdown dates decides, at call time, which model is sent; a model shut down with no successor is never sent, and the next configured provider takes over. A daily task warns 45 days before a model in use shuts down.

See `.drafts/v8.2.0-release-notes-and-walkthrough.md` Part 2 for the rest.

## Part 3: Admin Walkthrough Script: getting ready for OpenAI's speech shutdown (about 4 minutes, conversational)

### 1. Why (about 30 seconds)

"OpenAI turns off its text-to-speech models on the sixth of January. There's no OpenAI model that does the same job through the same request, so SOLA won't pretend there is. From that date it stops calling OpenAI for read aloud and uses the next voice row that can speak. We're going to add that row now."

### 2. Add a Gemini row (about 2 minutes)

Open **Site administration, Plugins, Local plugins, AI Course Assistant**, then **Advanced, Prompt, voice and display**. "Read the Voice providers description: it says the date and what to do." Press Add, choose Google Gemini, paste the key, label it `gemini-tts`, and put `gemini-3.8-flash-lite-tts` in TTS model. "That's the cheaper Gemini voice model." Save. Then set **Active TTS provider** to `gemini-tts` and save again.

### 3. Hear it (about 1 minute)

Open a course as a student, ask a question and press the speaker on the answer. "That's Gemini now. Nothing else changed: the microphone still goes to the same place."

### 4. Transcription (about 30 seconds)

"Speech to text moves on its own. On the twenty-sixth of February hosted OpenAI transcription switches from whisper-1 to gpt-transcribe, same endpoint. If you run your own Whisper server, nothing about it changes. Its model name is its own, even when it's called whisper-1."
