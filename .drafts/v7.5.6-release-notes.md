# SOLA v7.5.6: Release Notes

## Part 1: Release Notes (28 September 2026)

**One defect, reported with a screenshot, and it has been live since August.**

- **The consent notice was close to unreadable in dark mode.** The panel a learner sees the very first time they open the assistant carried the only `prefers-color-scheme` rule in the whole stylesheet: a dark background with light text. Its contents set their colours as inline styles in the template, and inline styles beat a media query on specificity, so the background went dark and the text did not follow. Measured on the shipped values: body text `#333` at **1.24:1**, the privacy link `#023e8a` at **1.53:1**, the scroll hint `#666` at **2.73:1**. WCAG AA asks for 4.5:1. The affected text is the privacy notice itself, so it was the worst thing on the page to make hard to read, at the one moment a learner is asked to consent to it.

### It is not a v7.5.5 regression

It came in with v7.2.7 on 31 August and is present in v7.4.1, which Saylor's Learn and Degrees sites have been running since 9 September. Every release from v7.2.7 to v7.5.5 carries it. v7.5.6 is the first that does not.

### Why the rule is removed rather than the colours fixed

The drawer behind the notice is hardcoded `background: #fff` and nothing else in the widget responds to `prefers-color-scheme`. The notice was the single dark surface in a light widget, and an orphan feature at that. On white, those same three colours measure 12.63:1, 10.20:1 and 5.74:1, all passing.

Giving the widget genuine dark-mode support is a real piece of work and worth doing on its own terms. Keeping one surface dark while its own text cannot follow is not a step toward it.

### Testing

`tests/consent_banner_contrast_test.php` computes WCAG relative luminance and checks every inline colour in the notice markup against whatever background the CSS gives it. It pins the arithmetic rather than the fix, so it stays meaningful if the widget later goes properly dark.

The contrast function is itself checked against known values, because a contrast function nobody has verified is how you get confident about a wrong number.

Both mutations caught: restoring the dark-mode rule, and changing a stated colour to something illegible.

### Everything else

Unchanged from v7.5.5. See those notes for the focus work, the configurable recording cap and the translated voice errors.

Plugin version `2026092801`, release `7.5.6`.
