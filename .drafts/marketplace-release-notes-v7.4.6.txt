v7.4.6 supersedes v7.4.1 through v7.4.5, none of which were submitted here, so these notes cover everything since v7.4.0.

It opens by correcting v7.4.0. That release described asymmetric query and document embedding as dropped in favor of a single shared embedding space "after failing to reproduce twice". That conclusion was wrong, and it conflated two different things that share the name. Pairing a larger model for documents than for queries genuinely did not reproduce. Sending Voyage its intended input_type hint, which is a different thing entirely, does reproduce and matters a great deal. Because of the error the plugin shipped a default that sends the same projection hint when indexing and when searching. On voyage-4-large that configuration measures 42.6% Recall@3, while the text-embedding-3-small index a Voyage migration is meant to replace measures 52.8%. A site could therefore pay to re-embed its entire corpus and retrieve 10.2 points worse than before it started. The vendor's intended mode measures 66.7% on the same stored vectors, 24.1 points better than the shipped default. The evidence is 816 anchored fixtures across 13 courses against a 17,257-chunk index, with the control arm reproducing its previously recorded baseline on all six recall figures. Switching the setting requires no re-index, because only the query-side projection changes and the stored document vectors are untouched. The default is corrected in both places that resolve it, the settings default and the runtime fallback, since a site with no stored value never consults the settings file. Existing sites keep whatever value they have, so this reads as "new installations are fixed" rather than "everyone is fixed", and the release notes carry a one-line recovery action for sites already running Voyage. A reranker had been masking the problem: shared plus reranking scores within a point of the incumbent, so an affected site could not have detected it from its own numbers while paying per query for a cross-encoder to undo a free configuration error.

Spend accounting was reading a floor rather than a bill. Five components made real, billable model calls that nothing recorded: the conversation classifier, the student profile manager, speech scoring, objective extraction and slide vision. Separately, reasoning tokens were never read at all although both major vendors report them, and three further endpoints persisted no usage. One month showed $3.96 of estimated spend against an $11.13 invoice. Reasoning tokens are now stored exactly as reported and never folded into completion tokens, because one vendor already includes them and another does not, so folding would double-count one while still undercounting the other. The coverage check is now structural rather than anecdotal: it scans the source for every usage type, and each must either appear in the billing predicate or be listed as not billable with a stated reason. It was confirmed by planting a sixth unlogged writer and watching the build fail. This class of bug had shipped three times, and a test that merely asserted rows existed had never caught it. Sites should expect reported spend to rise after upgrading with no change in actual spend.

Learning objectives can now come from curated data instead of guesswork. The plugin previously discovered objectives by scraping course content, walking the course summary, then each section summary, then every visible Page and Book, running each through the text filters looking for something bullet-shaped. That approach is both expensive and unreliable: when no heading pattern matches it falls back to reading bullets from the top of the document, which in practice yielded course names rather than objectives. Where the optional local_outcomemap plugin is installed, the plugin now reads approved, versioned outcome statements from its public API first, and returns before the content walk ever starts. The integration is guarded so that sites without that plugin behave exactly as before. Four call sites that formatted module content without first rewriting plugin file URLs are also fixed, and now pass the module's own context rather than falling back to the current page, which was wrong whenever the code ran outside that module's page and unavailable to scheduled tasks.

Scheduled analytics moved onto the vendor batch API at half price for input and output, which suits a slot that is offline and scheduled by definition. Batched calls carry a distinct model prefix so the discount reaches pricing and a batched call can never be mistaken for a synchronous one. The model registry now tracks end of life, recording which vendor surface a retirement date applies to, a distinction that exists because of a real near miss where a retirement date belonged to a different API from the one the plugin calls. Embedding calls also gained retry: embeddings were the only provider path with no backoff, so a single rate-limit response ended an all-or-nothing indexing run with no way for an operator to recover except to start again.

Smaller fixes. A restored course could carry a model identifier the site cannot serve, which rejected every chat turn in that course; restores now clear it and fall back to the site default. Streaming provider errors discarded the response body on any 4xx, so every failure surfaced as an HTTP status with nothing after the colon. A byte-wise prompt truncation could split a multibyte character, which both broke JSON encoding and prevented the closing untrusted-content marker from being re-added, making it a prompt-injection surface as well as a correctness bug. Speaking assignments can now sit in a course section as an ordinary activity, so placement, hiding, availability, backup and restore are all core behavior. Object storage can be round-trip tested from the self-test page before a learner discovers it is misconfigured. Two administration pages that were reachable only by typing their URL are now linked from the settings tree.

Upgrading is additive. Four upgrade steps run from the previous release: one column on the messages table, one new table, two columns on the small model registry table, and one metadata-only step. A rehearsed upgrade produced a database identical to a fresh installation across all 38 tables, 417 columns and 227 index rows, compared three ways with no differences, and Moodle's own schema checker passes on both. Nothing is dropped or rewritten and no existing row is modified.

Quality gate: 1,612 automated tests with no failures, and continuous integration across PHP 8.1 to 8.3 with MariaDB and PostgreSQL on Moodle 4.5, 5.0 and 5.1. The plugin ships 46 locales, and a translation-parity test fails the build when a new English string appears without translations unless it is explicitly staged as known debt, so every user-facing string added in this release is translated in all 45 non-English locales.
