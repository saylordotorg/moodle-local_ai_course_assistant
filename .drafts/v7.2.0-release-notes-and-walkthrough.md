# SOLA v7.2.0 — Release Notes, Feature Summary, and 20-minute Admin Walkthrough

## Part 1: Release Notes (27 August 2026)

### Moodle Marketplace review remediation

All seven findings from the CONTRIB-10574 review of 7.0.5 are addressed. Two were
repeats of findings from the June round, so those got a sweep rather than a fix to
the cited lines.

#### The approval blocker: no more self-updating

`classes/plugin_updater.php` renamed the installed plugin directory out from under
itself and moved extracted archive content into its place, driven from a web
request in `update_admin.php` with an admin-supplied `zip_url`. Both files are
gone, along with the settings heading, the update link, the `github_token`
setting and the admin page. Updates go through Moodle's normal
administrator-controlled upgrade path, which is the only sanctioned route.

The upgrade step also clears the stored values for those settings. `github_token`
held a credential for a feature that no longer exists; leaving it in
`config_plugins` would keep it on disk indefinitely.

#### Course backup and restore

Also HIGH, and the largest piece of work here. The plugin keyed per-course
configuration and per-learner activity on `courseid` with no `backup/moodle2`
implementation at all, so duplicating or restoring a course silently dropped every
bit of it.

Configuration travels always: per-course AI config, per-quiz assistance levels,
learning objectives, rubrics, Soapbox assignments with their topics. Learner
activity travels only when the backup includes users: conversations with their
messages and ratings, objective attempts, study plans, reminders, goals, streaks,
practice scores, flashcards.

Two things are deliberately withheld from the backup file. **Per-course API keys**,
because a course backup is a file administrators move between sites and email
around. And **reminder unsubscribe tokens**, which are per-site secrets; the
restore mints fresh ones. The **RAG index is not backed up either**: it is derived
data rebuilt by reindexing, and it is the largest table the plugin owns, so
carrying it inside every course backup would multiply backup size for nothing.
Restored courses need a reindex.

Ids are remapped rather than trusted. A `cmid` that does not resolve on the target
site is stored as null instead of being left pointing at whatever module happens
to hold that id — the same class of bug as the cross-course read fixed in v7.0.5.

#### Templates, Output API and AMD

`prompt_playground.php` loses 60 lines of echoed markup to a Mustache template.
`starter_settings.php` loses a 229-line inline `<script>` to
`amd/src/starter_admin.js`. Two inline blocks in `chat_widget.mustache` become
`amd/src/consent_gate.js` and `amd/src/student_mode.js`. An inline `onclick` that
toggled a sibling's display is now a native `<details>`, and fifteen inline
`style` attributes moved to `styles.css`.

Two `<script>` tags stay inline on purpose, with a comment saying why: they
bootstrap the standalone CDN bundle, which loads outside Moodle's AMD loader and
needs its i18n payload as a global before it runs.

A side effect worth having: the playground used to call `s()` by hand at each
interpolation. Mustache escapes `{{ }}` by default, so retrieved course content
and the assembled prompt are now escaped structurally rather than by remembering.

#### MySQL-only SQL, template headers, hard-coded text

The return-rate metric used `FROM_UNIXTIME(timecreated, '%Y-%m-%d')`, which is
fatal on Postgres — that metric could never have run on half the supported
platforms. Now `FLOOR(timecreated / 86400)`, which buckets by UTC day instead of
by the database session's timezone, and is arguably the steadier definition.
Swept for `DATE_FORMAT`, `DATEDIFF`, `CURDATE`, `GROUP_CONCAT` and `IFNULL`;
nothing else remained.

The reviewer found two Mustache templates missing the boilerplate header. There
were five. All 21 now carry it.

Seventeen strings were extracted from `settings.php`, where they were hard-coded
English: the section navigation, the two analytics quick-link cards, and the long
explainers for RAG and Realtime Voice Mode.

### Also in this release

An **absolute floor for the cost-anomaly digest**. The existing threshold is a
percentage, and a percentage on a small base is noise: daily token volume on Learn
swings between roughly 1.7M and 3.7M with nothing behind it, which clears the
default 50% routinely — and the day that produced a "76% up" alert cost $1.33 in
total. `anomaly_digest_floor_usd` withholds the alert unless the last 24 hours
priced above the floor, and the alert now states the cost when it can. Default 0,
so an upgrade does not silently start suppressing alerts. It fails open: if any
spend in the window comes from a model with no rate-card entry, the window cannot
be priced and the alert is sent anyway, because an unrecognized model in the mix
is itself worth seeing.

### Upgrade notes

- **One upgrade step, no schema change.** It clears the three dead self-updater
  settings.
- **Five AMD bundles rebuilt.** Purge caches after upgrading.
- **The plugin can no longer update itself.** If you were using that page, use
  Moodle's normal plugin installation flow instead.
- **Restored courses need a RAG reindex** if you use retrieval, since the index is
  deliberately not carried in backup files.

### Testing

Full suite 965 tests / 4,062 assertions / 0 failures. Validators 36/0. Lint clean
across every changed file; all 46 language files parse; all 21 templates carry the
header and have balanced section tags.

Backup and restore were tested by driving the real `backup_controller` and
`restore_controller` rather than asserting the classes exist — configuration
survives a duplicate, objectives are remapped, conversations come across with
users and are absent without them, the API key does not travel, and the RAG index
is confirmed excluded. All six were verified to fail with the backup directory
removed.

The consent gate was re-verified with its Puppeteer harness against a live site,
because moving that JavaScript could have broken a gate that has had two bugs
found in it before. Both migrated admin pages were loaded with an admin session
and checked for expected markup.

Plugin version `2026082700`, release `7.2.0`.

## Part 3: Admin Walkthrough

### Duplicate a course and check the AI settings came with it

The headline fix. Take a course with per-course AI configuration, duplicate it, and
open the copy's AI Course Assistant settings — provider, model and system prompt
should be there. The API key will not be, deliberately: re-enter it on the copy.
If you use retrieval, run a reindex on the copy.

### Look for the updates page, and confirm it is gone

Site administration → Plugins → Local plugins → AI Course Assistant. There is no
longer an "Updates" page or a GitHub token field. That is the approval blocker
resolved; use Moodle's plugin installer for future upgrades.

### Set the anomaly floor if the digest has been noisy

Under the anomaly digest settings, set *Minimum spend to alert on* to a daily
figure you would actually want waking you. On Saylor's volume, anything under a
few dollars a day is variation rather than an incident.
