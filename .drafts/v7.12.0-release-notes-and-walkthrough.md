# SOLA v7.12.0: Release Notes, Feature Summary, and Admin Walkthrough

## Part 1: Release Notes (19 October 2026)

## v7.12.0 (19 October 2026): Cleaning up after the new settings menu

**Why this release exists.** 7.10.0 regrouped the settings menu. It left a few things behind: one setting that was marked for removal a while ago, the daily task behind it, and strings and code that nothing uses now. This release removes them. It adds no setting, no feature and no string. If you never switched the old auto-tune setting on, you won't see a difference.

**The retired setting: `prompt_budget_auto_tune`.**

- **What it was.** A checkbox, "Auto-tune system prompt budget daily (deprecated)", on Advanced > Soapbox, avatars and legacy. When it was on, a daily task ("Auto-tune SOLA prompt budget from observed metrics", 03:20 server time) applied the budget recommendation that the Prompt metrics page shows. The settings page also showed a warning when the box was ticked while the budget mode was set to derive the budget from the model.
- **It already did nothing unless the budget mode was Fixed.** Since 7.2.6 the task has stood down unless **System prompt budget mode** is **Fixed character budget**. In the default mode, which works the budget out from the model's context window, it wrote nothing. It was marked deprecated then, to go after one release. This is that release.
- **What happens when you upgrade.**
  - The stored value of the setting is deleted. The upgrade writes no row to the configuration log for it.
  - The daily task is no longer scheduled. It's gone from Site administration > Server > Tasks > Scheduled tasks.
  - Your prompt budget keeps the last value it had. The upgrade doesn't touch **System prompt character budget** or the budget mode.
  - If the box was ticked and the mode was Fixed, the budget stops changing overnight.
- **To tune the budget, use the button.** Open **Prompt metrics + budget recommendation** in the AI Course Assistant list in Site administration and press **Apply recommendation**. The button is still there. It shows when there are at least 30 samples and the recommendation differs from the current budget. It writes the character budget. As before, in the default mode a budget other than the shipped default (36,000 characters) wins over the one derived from the model.
- **A signed policy bundle that still carries the key keeps working.** The key moved from the list of settings a bundle may set to a new list of retired keys. A retired key is accepted and ignored. It's never written to the site and it isn't listed as changed in the audit row. The bundle's other settings apply as usual. A bundle with any key that's on neither list is still rejected in full, and a retired key still has to hold a plain value like any other. `policy_bundle_tool.php --sign` now refuses to sign a payload that carries a retired key, so nobody builds a new bundle around a setting that does nothing. `--verify` still lists a bundle's settings as they were signed, and labels a retired key "retired, ignored". Dropping a name from the retired list is a major-version decision.

**Strings and code that nothing used.** None of this was visible, with one small exception: the **Advanced > Soapbox, avatars and legacy** page has a shorter English intro ("The deprecated Soapbox settings and the talking-avatar vendor settings."). Nothing else looks different.

- 23 strings are deleted from all 46 languages. They're the ten old page titles (`settingspage:pagetitle`, `ai`, `content`, `rerank`, `extraction`, `operations`, `feedback`, `engagement`, `branding`, `integrations`), the seven old section titles (`settingspage:sec_*`), the two table-of-contents strings (`toc_heading`, `toc_save`), and four strings from the old auto-tune toggle on the Prompt metrics page (`prompt_metrics:auto_tune_heading`, `auto_tune_on`, `auto_tune_off`, `settings_link`). Those four still described a nightly auto-apply that no longer exists. The other languages lose only strings that nothing used. `settingspage:safety` stays: it's the title of the Safety and privacy page.
- The retired setting's own strings go with it: its label, its description, its warning and the task's name, in every language, plus the English-only "Deprecated settings" heading.
- In `settings.php`, the eight section anchor notices and the `$sectionanchor` helper that built them are deleted, along with two CSS rules that styled them and their eight entries in the layout map's dropped list. 7.10.0 had already stopped showing them. The eleven staging pages that `settings.php` builds, which nobody ever sees, are titled with their own id now instead of a language string.

**Deliberately left alone.**

- **Soapbox.** It's still deprecated. The notices in the product promise that no release removes it until PresenterAI can import existing recordings and scores, and that importer doesn't exist yet.
- **The talking-avatar settings.** They stay where 7.10.0 put them, on Advanced > Soapbox, avatars and legacy. They're parked, not cut, because the decision on talking avatars isn't made.
- **`provider_keys_displaced`.** The 7.9.0 upgrade keeps the old key of any row it overwrote there, concealed. Deleting it in the same upgrade chain as the step that writes it would erase the key it exists to keep, so it stays.
- **Settings that were never changed.** They're still not deleted. That needs the evidence from the 7.10.0 usage report and a decision, not a cleanup.

**What the upgrade does to your site.** It deletes one stored setting, `prompt_budget_auto_tune`, and Moodle drops the schedule of one task. That's all. There's no schema change, no new setting, no new capability and no new string. **After you upgrade, purge caches,** as with any release that removes strings.

**Decisions behind this release.**

- This release is a cleanup, not 8.0.0. 8.0.0 stays reserved for removing Soapbox, which can't happen yet.
- The retired key is accepted, not rejected. A bundle that's already signed and published can't be edited, and rejecting it would also drop all its other settings.
- The upgrade deletes the flag and nothing else. The budget is the administrator's, so it stays as the last tune left it.
- Marketplace upload isn't part of this release.

**Known limits.**

- Custom code or a script of yours that reads `prompt_budget_auto_tune` gets nothing now.
- The key stays on the retired list until a major version. A bundle can carry it until then.

**Production.** Saylor's production sites (Learn and Degrees) stay on 7.5.7, frozen until 2027. 7.12.0 reaches them only when Catalyst upgrades them, and the upgrade step runs then. If either site still has the box ticked with the budget mode set to Fixed, its nightly budget update stops at that point. This release goes to the dev fleet (dev.sylr.org and alpha.sylr.org) and GitHub. The Marketplace upload isn't part of it.

### Testing

- 7 new tests in `prompt_budget_auto_tune_retirement_test` run the real upgrade step (`2026101803`) and check the task:
  - the stored flag is gone and the savepoint is reached, and the step calls `unset_config()` without a log argument;
  - a site with the box ticked and the mode Fixed keeps its mode and its budget, and nothing is thrown;
  - a flag that was never stored is harmless, other settings are untouched, and no configuration log row is written;
  - after core's reset of scheduled tasks, the task's schedule row, its class and its entry in `db/tasks.php` are gone;
  - `apply_recommendation()` and the Apply recommendation button still exist and work by hand.
- 9 new tests in `policy_bundle_test`: the retired list names the key and the allowed list doesn't; a bundle with an allowed key and the retired key applies the allowed one and never writes the retired one, even over a value the site still holds; a bundle that carries only the retired key is accepted; the audit row and the managed-keys list leave it out; a retired key next to an unknown key is still rejected whole; a retired key with an array value is rejected; and the automatic model switcher refuses to write it.
- `lang_completeness_test` lists the 23 removed keys and fails if one comes back in any of the 46 locale files or if any PHP, JS or Mustache file references one. `settings_page_structure_test` fails if a section anchor, a `$sectionanchor` helper or a language-titled staging page returns. `settings_layout_test` now lists `prompt_budget_auto_tune` as removed on purpose, so the defaults pin can't hide a changed default, and holds the dropped list to the one heading that still exists.
- The guards that matter most were each proven by planting the defect and watching a test fail, with `scripts/prove_test.py`: the retired-key allowance dropped from verification, the apply loop and the managed-keys write each reading the raw payload instead of the live settings, the key put back on the allowed list, the `unset_config()` call removed from the upgrade step, a removed setting listed in the layout map, a removed string put back into one locale file, and a section anchor or a language-titled staging page put back.
- No chat, prompt, provider or retrieval code changed in this release. The code changes are the retired list in `policy_bundle`, the upgrade step, the removal of the setting and its task, the `--sign` refusal and a few comments.
- Release step, not filled in yet: the full suite on the release commit, the CI result, and the dev and alpha deploy check.

Plugin version `2026101803`, release `7.12.0`.

## Part 2: Key SOLA Features

What the plugin does as of v7.12.0, for an admin deciding what to switch on.

- **A tutor that knows the course.** Answers come from the course itself, with
  optional semantic retrieval over pages, books, PDF, DOCX, PPTX, H5P and SCORM
  content and video transcripts.
- **Practice built in.** Practice quizzes, flashcards, worked examples, study
  plans with reminders, and essay feedback against a rubric. Practice only,
  never a Moodle grade.
- **Steps back during assessment.** While a learner has a quiz attempt open, the
  assistant is unavailable to them everywhere, including outside the course.
- **Support outside courses** (optional). On the dashboard and site pages it
  answers enrolment, certificate and technical questions from a support course
  and the FAQ, with its own three starters, and can hand off to Zendesk.
- **Readable answers.** Headings, lists, tables, quotes and code render in the
  chat, and an answer that runs out of room says so rather than stopping
  silently.
- **46 languages**, with automatic reply-in-your-language, speech input and
  output, and an optional live voice mode. Works on phones, including with
  Moodle's menu drawer open.
- **Any provider, one table of keys.** Gemini, OpenAI, Claude (including Opus
  5.5 and Sonnet 5.5), DeepSeek, Mistral, xAI, MiniMax, OpenRouter, Together,
  Ollama, Moodle's own AI subsystem, or any OpenAI-compatible endpoint. Every
  provider's key, models and base URL live in one **Providers and keys** table,
  so you can add or change a key without touching the default provider.
  Embedding, Rerank and Voice can use a row's key instead of a pasted copy.
  Failover, a premium tier for hard turns (Claude Sonnet 5, benchmark-backed),
  and spend caps per course.
- **Keeps up with new models.** It knows what each model accepts from data
  rather than name checks, fixes a rejected request by itself, and (unless an
  admin turns it off) tests newer models nightly and switches to one that's
  the same price or cheaper and at least as good, rolling back if live answers
  get worse.
- **Costs you can see.** A model registry with prices and their sources, a daily
  price-drift check, token analytics, cost anomaly alerts and benchmarks.
- **Safe defaults.** Nothing contacts a third party until an admin configures
  it: remote configuration, the Python sandbox runtime and the CDN delivery all
  default to off. The assistant opens by itself only on course pages, and only
  if an admin turns auto-open on.
- **Keys encrypted at rest, never shown, and replaced in one step.** Provider
  keys, the Voice providers table, webhook URLs and every other secret are
  stored with Moodle's own encryption, so a database backup alone doesn't
  reveal them. No settings page ever shows a key: a saved one reads "Saved, ends
  in ab12", and the settings-changed notice and Moodle's configuration log hide
  secrets too. A command lists where each key is stored (by its last four
  characters only) and replaces one key everywhere in a single transaction, and
  a Reports > Status check flags a key kept in several places.
- **White-label.** Four settings rename the whole product, in every language.
- **Instructor views.** Analytics, a review queue for learner feedback, Learning
  Radar, transcripts with pseudonyms, and surveys with validated rating scales.
- **Python sandbox** (per course). Runs in the learner's browser, never on the
  server, and shows the full error when code fails.
- **Soapbox** remains deprecated, and no release removes it until PresenterAI can
  import existing recordings and scores; its replacement is the standalone
  PresenterAI activity.

## Part 3: Admin Walkthrough Script: after the cleanup (about 5 minutes, conversational)

This is written to be read aloud while you click. It assumes a test site that has just upgraded to 7.12.0 (the dev fleet is the place for it) and an admin login. Step 4 needs a shell on the server and a signed policy bundle, and you can skip it if you don't use bundles. For the menu itself, see the 7.10.0 walkthrough.

### 1. Purge caches and look at Status (about 1 minute)

"First thing after any upgrade: purge caches." Do that under **Site administration, Development, Purge caches**. Then open **Site administration, Reports, Status**.

"Nothing here should be new. This release didn't add a check or change one, so anything amber or red was already there before the upgrade." If a SOLA check does show up that you don't recognize, stop and read it before going on.

### 2. The deprecated setting is gone (about 1 minute)

Open **Site administration, Plugins, Local plugins, AI Course Assistant, Advanced, Soapbox, avatars and legacy**.

"This page used to end with a short section called **Deprecated settings**, and in it one checkbox: **Auto-tune system prompt budget daily (deprecated)**." Scroll to the bottom. It isn't there. "What's left is Soapbox, which is still deprecated and still here, and the talking-avatar settings. Those are staying, on purpose."

Now type `auto-tune` into the Site administration search box. "Nothing from SOLA comes up." Then open **Site administration, Server, Tasks, Scheduled tasks** and look for **Auto-tune SOLA prompt budget from observed metrics**. "It's gone from the list too. The upgrade removed the task's schedule, and the other SOLA tasks are still there."

### 3. Tune the budget by hand (about 1 minute)

Back under **AI Course Assistant**, open **Prompt metrics + budget recommendation**.

"The recommendation was always on this page, and it still is." If the site has at least 30 samples and the recommendation differs from the current budget, the page shows both numbers, the reason, and an **Apply recommendation** button. If there's too little data, it says so. "That button is the only way to apply a recommendation now. Nothing does it for you overnight." Don't press it unless you want the budget to change. "It writes the **System prompt character budget**. In the default mode, a budget that isn't the shipped default of 36,000 characters wins over the one derived from the model, so pressing it means you've chosen a fixed number."

### 4. A policy bundle dry run, if you have one (about 2 minutes)

"Only if you use signed bundles. If you don't, skip this one." From the Moodle root:

```bash
sudo -u www-data php local/ai_course_assistant/admin/cli/policy_bundle_tool.php --verify --bundle=signed.json
```

It prints `VERIFY OK`, then the bundle's version, comment and settings. "Verifying changes nothing on the site." If the bundle was signed before this release and still carries `prompt_budget_auto_tune`, it's listed here, labelled "retired, ignored", and the bundle still verifies. "That's the point. The next sync applies the other settings, ignores that one, and the audit row for the sync doesn't list it as changed."

Then run `--status` to see the applied version and the result of the last sync. "If you want to see the other half, put `prompt_budget_auto_tune` in a payload and try to sign it." The tool stops with: `setting 'prompt_budget_auto_tune' is retired and does nothing; remove it from the payload before signing`. "Old bundles keep working, but you can't build a new one around it."

### 5. Nothing else moved (about 30 seconds)

Click through the five task pages once: **Essentials**, **Models and keys**, **Features**, **Safety and privacy** and **Cost and reliability**. "Everything is where 7.10.0 put it. This release didn't change a page you use, and every old string that's gone was one nobody could see."
