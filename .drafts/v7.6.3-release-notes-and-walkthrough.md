# SOLA v7.6.3: Release Notes

## Part 1: Release Notes (2 October 2026)

## v7.6.3 (2 October 2026): the admin pages move to templates

A rendering change. Five admin pages stop building HTML and JavaScript inside
PHP and start using Moodle's template and module system instead. Nothing a
learner or an administrator sees is meant to change, and no capability check,
login gate or save path moved.

About 1,900 lines leave the PHP files: rubric_admin, survey_admin,
usertesting_admin, soapbox and course_settings. Each page's markup is now one or
more templates, each page's inline script is an AMD module, and the data a
script needs travels in a data attribute rather than as arguments to
js_call_amd, which is the limit that v7.6.0 fixed on the conversation-starter
page.

Four defects were found reviewing the change and are fixed in it.

**Two were introduced by the migration.** The survey admin page fatalled to a
blank screen if a survey row held a NULL or truncated question list, where the
old code still rendered a usable page. And moving the global system prompt into
a data attribute put it somewhere the page smoke test reads: the shipped default
prompt contains a branding token, so the test failed on every site whose prompt
had not been blanked. It passed locally only because the development box happens
to have an empty prompt.

**Two were older and systemic.** A template variable placed immediately after a
textarea tag loses a leading newline, because the HTML parser removes exactly
one there, and the next save makes the loss permanent. The inline scripts this
replaces set the value as a property and never had the problem. Seven templates
carried the pattern.

And repainting a card list is asynchronous now where it used to be immediate, so
handlers attached to cards still on screen could act on positions that had
already shifted. Deleting one row and then another before the repaint landed
could remove the wrong one. Cards from a superseded render now refuse clicks.

Also: the golden-prompt benchmark CLI gains a repeats option. It had none, so
running three repeats per provider meant running the whole script three times
and merging the files by hand. Each row now records its repeat number, the
account that produced it, and a fingerprint of the system prompt it ran under.

2,018 tests, 0 failures, 7 skipped. Validators 36 of 36.

## Part 3: Admin Walkthrough

Unchanged from v7.5.7, with one addition: after upgrading, check Site administration, Plugins, Local plugins, AI Course Assistant, and confirm "Remote config URL" is empty. If your site had never set it, the upgrade has cleared it and remote configuration is now off. If you had set your own URL, it is untouched and still active.
