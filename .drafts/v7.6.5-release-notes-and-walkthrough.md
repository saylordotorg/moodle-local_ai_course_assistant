# SOLA v7.6.5: Release Notes

## Part 1: Release Notes (3 October 2026)

## v7.6.5 (3 October 2026): rating scales that cannot be configured into a dead end, and a chat that sits where you expect it

**The conversation now sits just above the box you type in.**
A short exchange used to float at the top of the drawer with a tall gap beneath
it, so the assistant's newest reply was the furthest thing from the composer.
The transcript is bottom-aligned now, which is how every other chat you use
behaves. It is done with an auto top margin on a zero-height spacer rather than
`justify-content: flex-end`, because on a scrollable flex column that property
makes browsers clip the top of a long transcript and strand it out of reach.

**A survey rating question could be configured so that nobody could answer it.**
The admin form's number inputs carry `min` and `max` attributes, but those are
advisory and the POST body is the only thing that counts. Nothing checked the
bounds, so a scale saved as 5 to 1 stored cleanly and then rendered with no
buttons at all, because the render loop is `for (r = min; r <= max; r++)` and it
simply never runs. The learner was shown a required question with nothing to
click. A large enough maximum built one button and one click handler per step
for every learner who opened the survey.

The save path now refuses a scale outside 1 to 10 or entered backwards, and says
so instead of silently correcting it. Surveys already stored badly are repaired,
once, by an upgrade step that logs the old and new bounds, so the data on disk
matches what is shown and the change is dated rather than happening invisibly at
render time.

**The same two unchecked lines were in the user-testing page.**
It was written from the same template and has the identical defect, except worse
in two ways: its tasks post as a single JSON blob so the browser never sees the
numbers at all, and it had no read-side repair of any kind. A rating task stored
backwards gave the learner a panel with no buttons that the code would not let
them advance past. Both pages are fixed the same way.

**Survey results add up again.**
Repairing a scale moved the histogram's buckets, and answers recorded under the
old scale fell outside them. They vanished from the bars while still counting
toward the response total and the average, so an instructor saw a chart that
could not be reconciled with the number beside it and nothing explaining the
gap. Out-of-scale answers are now folded in, blank and non-numeric rows no
longer invent a zero bar or drag the mean down, and the average is printed
against the question's own scale instead of a hardcoded "/ 5".

**The teacher transcript export leaked the assistant's internal markers.**
Both live write paths strip `[SOLA_NEXT]`, `[SOURCE:...]` and `[SOLA_SCORE]`
before storing, so anything written since those fixes is clean. That does
nothing for rows already in the table from before, and the CSV copied the
stored text straight through, so a teacher opening an export of older
conversations read the raw markers. It strips on read now too.

**Three other places took an admin number and trusted it.**
The demo seeder would create as many accounts as it was asked for: a large value
quietly created and enrolled thousands of permanent users, and a very large one
died on the memory limit before the page's error handling could catch it. The
analytics page's `range` reached a one-array-per-day fill loop with no ceiling,
on a plain GET with no sesskey, so an admin could be walked into it from a
crafted link. Both are bounded now, at the page and again inside the function so
no caller can bypass it.

## Part 3: Admin Walkthrough

Unchanged from v7.5.7, with one addition: after upgrading, check Site administration, Plugins, Local plugins, AI Course Assistant, and confirm "Remote config URL" is empty. If your site had never set it, the upgrade has cleared it and remote configuration is now off. If you had set your own URL, it is untouched and still active.
