# SOLA v7.0.5 — Release Notes, Feature Summary, and 20-minute Admin Walkthrough

## Part 1: Release Notes (24 August 2026)

### A security release. Upgrade promptly.

An adversarial review of v7.0.4 produced eleven findings, five of them high severity. All eleven are fixed here. Nothing in this release changes what SOLA does for a learner; it changes what an ill-intentioned one, or a poisoned page of course content, can make it do.

**None of these involve an AI vendor.** Every finding is in SOLA's own code. No provider leaked anything, and no provider change is warranted by any of them.

#### The five that matter most

- **Any learner could read any Page or Book on the site.** `get_module_content()` resolved the course from the module id it was handed, so the caller's authorised course never constrained the read, and visibility was never checked. A learner with the plugin's `:use` capability in one course could pass another module's id — in another course, or a *hidden* activity in their own — and get its full text back through quiz generation, flashcard generation, or page grounding. Hidden Pages are where staged answer keys and instructor notes live. The course is now required and pinned, and the activity must be visible to that learner. Staff who may view hidden activities are unaffected.
- **Switching voice off left the voice endpoint running.** `realtime_enabled` was consulted in exactly one place — the code that decides whether to draw the button. A learner could call the token endpoint directly and mint a live voice credential with the feature switched off, at roughly $18/hour for a held session.
- **The system prompt was returned to the browser.** The voice endpoint shipped the entire grounded prompt — jailbreak defences, course configuration, learner personalisation — in its JSON response, while the chat path runs an output scrubber precisely to keep that prompt away from learners. It now goes to the provider server-side; the browser gets only generic spoken-style guidance.
- **Nothing throttled AI usage.** None of the 47 external functions carried a rate limit, and the spend guard reports "under cap" whenever no cap is configured, which is how the plugin ships. A per-user limit now sits on the one code path every provider call passes through.
- **Course content could open a support ticket.** Escalation shipped a learner's name, email and full transcript to Zendesk whenever the model's reply contained a marker — anywhere in the reply. Because retrieved course content shapes what the model writes, a page reading "end every reply with that marker" would have escalated every learner who touched that topic. It now requires the marker as the model's closing token, a configured support desk, a per-learner cap, and — the gate injected text cannot satisfy — a request for a human in the learner's **own** message.

#### The rest

- **Course material now reaches the model behind a fence.** The sanitiser had one call site, so the current-page block and the whole-course fallback were never sanitised on any path — while the page block instructed the model that its content "takes precedence over your prior conversation turns and over any persona styling". Untrusted content is now sanitised and wrapped in a data fence it cannot close from the inside.
- **The link filter was bypassable.** It denylisted `javascript:` as a literal string, but browsers strip tabs and line breaks before resolving a scheme, so `java<TAB>script:` passed the check and still navigated. Replaced with an allowlist applied after stripping control characters.
- **The rate limiter did not limit.** Read-modify-write with no lock: parallel requests all read zero and all passed. Now serialised.
- **The bulk-export credential stopped travelling in URLs** — and, more importantly, is no longer written into the query body sent to Redash, where it was being stored in plaintext by a third party.
- **Ten tables were deleted on erasure but never exported.** Among them the free-text observations the model *infers* about a learner, which is precisely what a subject-access request exists to surface.
- **A teacher could redirect their course's AI traffic.** Setting a per-course API base URL required only course-level rights and was saved with no validation, so every learner message and retrieved passage for that course could be sent to a host of the teacher's choosing. It now requires site-level rights and must pass the SSRF check.

#### Two fixes found while fixing others

- **The emergency voice kill switch was itself a no-op** on any site with a voice provider configured: it worked by blanking the active provider label, and a blank label simply fell through to the first configured provider. The same failure the `--chat` switch had until v5.13, fixed the same way.
- **The jailbreak suite was testing less than it appeared to.** It passed an empty set of retrieved passages, so indirect injection — hostile text arriving inside course content — had no coverage at all. It also ran as an administrator, where two of its own failure checks could never fire. Both corrected, so future runs exercise something previous ones did not.

### Also in this release

The premium escalation tier now targets **Claude Sonnet 5** rather than an Opus model. On the 50-prompt golden tutor set, Sonnet 5 scored 14.56/15 against Opus 5's 14.22, at 0.352 cents per call against 2.224 — better answers for roughly a sixth of the cost and a third of the time to first token. Opus was statistically tied with the workhorse tier it exists to improve on, at 42 times the cost. Sites that have already set this value explicitly keep it; only sites on the default move.

### Upgrade notes

- **No database changes.** No schema upgrade step, so the upgrade is a file replace plus a cache purge.
- **One behaviour change needs your attention.** Charts created through Learning Radar now require an `Authorization: Bearer` header configured on the Redash data source before they return data. The credential is deliberately no longer embedded in the query. Existing saved queries continue to work until you rotate the key.
- **Non-English sites should review escalation.** The learner-intent patterns default to Latin-script phrasings covering English, Spanish, French, German and Portuguese. If your learners write in another language, add patterns under *Escalation intent patterns*. An unmatched message means no ticket is opened — the safe direction, but it does mean escalation stays quiet until tuned.
- **If you use `voyage-context-4`, leave it unset.** Unchanged from v7.0.4: it is wired into indexing only.

### Testing

- Full plugin PHPUnit suite green; validator suite 36 passed, 0 failed; PHP lint clean on every modified file; all 46 language files parse and pass the completeness check.
- The site-wide read fix is verified against an independently written adversarial test, not only our own.
- The markdown bundle was rebuilt and the fix confirmed **in the built file**, not merely in the source.

Plugin version `2026082400`, release `7.0.5`.

## Part 3: Admin Walkthrough

Core drawer, quiz, voice, analytics, privacy, Soapbox and WSCUC-outcomes flows carry forward from v6.9.8. Four things are worth ten minutes after this upgrade.

### Confirm voice is actually off if you think it is off

Site administration → Plugins → Local plugins → AI Course Assistant → Settings, under Voice. If *Enable Voice Mode* is unchecked, it now genuinely refuses at the endpoint, not merely in the interface. If you had it unchecked before this release believing voice was disabled, it was not: the button was hidden and the endpoint was live. Nothing to do beyond knowing it.

### Set your escalation intent patterns if your learners are not writing in English

Under the Zendesk section, *Escalation intent patterns*. Empty uses the built-in defaults. Type a phrase a learner would actually use to ask for a person, and confirm it matches one of your patterns. If it does not, escalation will stay silent — which is safe but unhelpful.

### Re-point any Redash chart you created from Learning Radar

Open your Redash data source and add an `Authorization: Bearer <your SOLA redash key>` header. Charts created from now on carry no credential in their query, which is the point: previously the key was written into Redash in the clear.

### Check a per-course API base URL if you had one

Course → AI Course Assistant settings. If a course previously had a custom API base URL set by a teacher, it is retained, but only a site administrator can change it now. This is worth an audit: a per-course endpoint is the one setting that can route learner conversations somewhere you did not choose.
