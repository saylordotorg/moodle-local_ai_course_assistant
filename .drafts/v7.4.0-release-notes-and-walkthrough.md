# SOLA v7.4.0 — Release Notes, Feature Summary, and 20-minute Admin Walkthrough

## Part 1: Release Notes (8 September 2026)

**Keeping up with models and prices without a code change.** The constraint
behind this release is that after the next production deploy there are no code
changes and no filesystem access, so all of it has to be operable from the
admin UI and the database.

- **A model registry with provenance.** Three layers — committed baseline, the
  legacy override blob, then a per-key table that wins — and the admin page
  shows which layer supplied each price, who set it and when. An automated feed
  can no longer overwrite a human correction, which fixes a real defect: the
  weekly refresher used to replace the whole override blob and destroyed
  hand-entered prices every Monday.
- **The bug that made it urgent:** gemini-2.5-flash had no rate entry, so every
  chat turn on the fleet's primary model computed as $0.00 — no cap could trip
  and every cost figure was a floor. Corrected to $0.30/$2.50, along with the
  Anthropic rows, which were a generation stale.
- **Price drift that runs itself.** Pricing sources are database rows with a
  declarative parse spec, so adding a vendor feed later is a form rather than a
  class. Findings are proposed, never applied silently, and the top severity is
  "a model in traffic has no price at all", not "a price moved".
- **Benchmarks became data.** The golden-set harness already computed quality,
  cost and latency and then discarded it into a CSV; it now persists, any
  registry key can be benchmarked from the web, and the recommender refuses to
  compare when the sample is too small or spans a release — instead of quietly
  substituting a neutral score.
- **Spend reporting to the Saylor AI Spend dashboard.** The dashboard pulls, so
  the plugin now speaks its month-and-bearer contract directly and the Redash
  hop can be retired. Off by default, and it reports how many rows it could not
  price so a silent zero is distinguishable from a real one.
- **RAG:** reranker length-gated at 50 characters (better and a third cheaper),
  asymmetric retrieval dropped for one shared embedding space, voyage-4-large
  @2048 supported with a parallelized shadow-writing migration, and three fixes
  to the benchmark harness. No change to the chat stack.
- **Two defects reported by an outside user on Moodle 5.1 (#218):** a comment
  containing a PHP close tag made the course-settings page serve its own source
  and removed the only way to clear a per-course API key; and the shipped
  default provider was fatal on every Moodle 5.x. CI now tests 5.0 and 5.1,
  which is what would have caught the second.
- **CI:** main had been red for four days and two releases were tagged through
  it; the CDN bundle had been frozen three releases behind. Both fixed, with the
  validator suite now actually gating and two new guards for the failure classes
  involved.

### Testing

- 1,469 tests, 0 failures. Validators 36/36. i18n 46/46. Page smoke 35/35.
- Verified on Moodle 4.5, 5.0 and 5.1 in CI.

Plugin version `2026091000`, release `7.4.0`.

## Part 2: Key SOLA Features

Carried forward from v7.2.3. No feature changes. Admin settings added since
then: System prompt budget mode (7.2.4), quiz-lock scope (7.2.5), and a
settings-page warning when auto budget mode has no context window to derive
from (7.2.7). One new admin CLI, `audit_config_log_secrets.php` (7.2.4). The
budget auto-tuner is deprecated as of 7.2.6 and stands down unless the budget
mode is `fixed`.

## Part 3: Admin Walkthrough

### 1. Finish a quiz and immediately ask a question

Start an attempt on a quiz in a course, confirm the drawer is disabled and shows
the integrity notice, submit the attempt, then send a message in the same course.

**Expected:** it answers immediately. The lock lifts on submission, not when a
freshness window expires. Before this release it would keep refusing — and would
also refuse in every other course you opened.

### 2. Confirm the lock does not follow you between courses

With an attempt open in course A, open the assistant in course B.

**Expected:** course B works normally. Only course A is locked. If you want the
old site-wide behavior, Site administration → AI Course Assistant → *How far the
lock reaches* → **Every course**.

Worth knowing why the default changed: an abandoned attempt stays `inprogress`
forever, so under site-wide scope one forgotten quiz anywhere in a learner's
history disables the assistant in all their courses permanently.

### 3. Check that the input is disabled exactly when the server will refuse

While an attempt is open, open the drawer in that course.

**Expected:** the textarea and all six starter chips are disabled, and the notice
names the remedy — submit or close the attempt. There should be no state where
the box looks usable and the send is then refused.

### 4. Reload a conversation that had a failed turn

Open a course conversation with history.

**Expected:** zero occurrences of `core\`, `exception`, or `moodle_` anywhere in
the transcript. Old rows stored before 7.2.4 render the same learner-facing
notice as new ones.

### 5. Analytics with All courses selected

Site administration → Analytics, picker on **All courses**.

**Expected:** TOTAL ENROLLED carries a real number, at least as large as any
single course and at least as large as ACTIVE AI USERS. The two measure
different things: TOTAL ENROLLED is active enrollments, ACTIVE AI USERS is
people who actually used SOLA, so the gap between them is your adoption rate.
MSGS / ACTIVE USER divides by the second of those, not the first — which is why
both tiles were renamed in this release.

### 6. Read the privacy notice next to the audit log

Open the learner privacy notice, then the admin audit log.

**Expected:** the notice says SOLA keeps no record of its own of your name, and
that a name shown alongside SOLA data comes from your existing Moodle account.
That should read as consistent with the audit log showing full names.
