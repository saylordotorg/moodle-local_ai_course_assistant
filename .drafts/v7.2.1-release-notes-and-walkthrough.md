# SOLA v7.2.1 — Release Notes, Feature Summary, and 20-minute Admin Walkthrough

## Part 1: Release Notes (28 August 2026)

### Retrieved course content reaches the model again

Thirteen findings from a hands-on verification pass over v7.2.0 on the Catalyst
staging site: sixteen admin surfaces, the learner chat drawer, and a full course
backup and restore cycle. One blocker, three highs, six mediums, three lows.

**The blocker.** Retrieval was healthy — 258 of 258 chunks embedded in the test
course, real passages returned with plausible scores — and none of that text
reached the model. The shipped default prompt template carries `{{coursecontent}}`,
so the passages were substituted into the identity block, which is budgeted from
the `safety_identity` bucket: 10% of the prompt budget, sized for a 1.6 KB block.
Meanwhile the `course_content` bucket, 40% of the budget, was never spent — no
section had ever been created under that name, so it had been dead since v5.6.0.

The passages were truncated away while the prompt still instructed the model to
cite them inline. It duly cited passages it had never been shown: a five-step
framework that is not in the course, a NOAA photograph caption belonging to a
different image, and an artwork not discussed in the unit asked about. Every
grounded answer and every citation in production was coming from model priors.

The tell was that the assembled prompt did not change length when retrieval
returned more chunks. It does now:

```
before   0 chunks → 11,908 chars    2 → 11,146    5 → 11,146
after    0 chunks → 15,888 chars    2 → 20,403    5 → 23,467
```

**The prompt budget was smaller than the prompt.** A stock prompt with retrieval
on measures about 23,800 characters against a 12,000 default, so the assembler
dropped or truncated something on every single turn. Raised to 24,000. Sites still
on the old default are moved automatically; a tuned value is left alone.

**The chat kill switch did not stop chat.** Three independent faults, any one
sufficient. A missing `use` statement meant the spend guard, its failover and the
per-call failover chain had all been throwing a fatal error into a silent catch —
inert at the one point every provider call passes through, with no symptom. The
emergency stop was then treated as a spend cap and answered by switching
providers. And the guard exempted site administrators, who were the people
testing it.

**Every analytics chart was blank.** Chart.js prefers AMD when it sees a loader,
and Moodle always has one, so the library never installed itself. The dashboard
turned that into three empty canvases that read as missing data.

**Only five per-course fields survived a course backup.** Provider, model, system
prompt and temperature travelled. Socratic mode, flashcards, sandbox, essay
feedback, Soapbox, worked examples, external resources, the voice tab, auto-open,
digest email, English lock, the retrieval toggle, the widget choice and all seven
starter chips did not. A duplicated course kept its model and prompt — so the copy
looked correct — while every pedagogy decision quietly reverted to site default.

### Also in this release

- An audit log viewer. The rows were always written and nothing could read them,
  while two settings told administrators to go and look.
- Four unresolved `[[tutorshort]]` tokens on the Emergency Controls page, and five
  Prompt Playground labels printing their own HTML tags.
- The anomaly spend floor accepted `-5` and rejected `25.50`.
- A stripped citation marker left a space before the punctuation — which was the
  only user-visible trace of the blocker.

### Upgrade notes

- `prompt_budget_chars` moves from 12,000 to 24,000 **only if it is still on the
  old default**. If you lowered it deliberately for cost, it is left alone — and
  you should know that the assembled prompt will not fit below roughly 24,000.
- The emergency chat switch now stops every AI call, for administrators and
  scheduled tasks as well as learners. The backend self-test and health check stay
  available so you can verify the provider before restoring. Its description has
  been rewritten in all 46 languages to say so.
- Per-course settings now travel in course backups. Restoring into a course that
  already has an override will not overwrite it.
- No schema change. One upgrade step, which only touches the budget setting.

### Testing

988 PHPUnit tests, 4,108 assertions, no failures. 36 of 36 validators. New
regression cover for the blocker (four of its five tests fail against the previous
builder), the kill switch, the backup round trip, and the backup allowlist. The
Chart.js fix was verified A/B in a browser with RequireJS present. The fixes were
then put through code review, which found ten further issues — including one that
was the same over-subscription bug at reduced magnitude — all of which are fixed
here.

## Part 3: Admin Walkthrough

### Ask a course question and check the answer is grounded

The headline fix, and it takes two minutes. Open a course with retrieval enabled
and an index built, and ask something answerable only from the course text — a
specific figure, a named example, a caption. Before this release the answer would
be fluent and invented. Now it should quote the course, and any `[[c:N]]` citation
should correspond to a real passage.

If you want to see the mechanism, Prompt Playground now shows the retrieved chunks
inside the prompt it displays. Before, it reported "5 chunks fed to the prompt"
above a prompt containing none of them.

### Duplicate a course and check the pedagogy settings came with it

Take a course with Socratic mode forced on and flashcards forced off, duplicate
it, and open the copy's AI settings. Both should have travelled, along with the
starter chips and the retrieval toggle. The API key still will not, deliberately.

### Test the emergency chat switch — as a student

Site administration → the red **Emergency Controls** link. Disable chat, then open
a course in a private window logged in as a test student and try to chat. You
should get a short paused notice. Then check it as an administrator too: it stops
you as well now, which is the point.

While it is paused, open the backend self-test. It should still work — that is
deliberate, so you can confirm the provider is healthy before restoring.

### Look at the analytics charts

Site administration → the Analytics link. The three charts on the overview tab
should draw. If they are empty, the console will now say why rather than leaving
you to conclude you have no data.

### Read the audit log

New page, linked from the settings quicklinks. Every emergency switch, provider
failover and de-anonymised export is listed. Read-only.
