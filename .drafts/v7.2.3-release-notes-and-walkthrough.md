# SOLA v7.2.3 — Release Notes, Feature Summary, and 20-minute Admin Walkthrough

## Part 1: Release Notes (28 August 2026)

### The budget was still too small, and two charts were still dead

A verification pass over 7.2.1 confirmed all nine of its fixes, then found that
the headline one had been given too little room to work in. This release closes
that, plus the backup limitation 7.2.2 documented rather than fixed.

**24,000 characters was not enough.** The 7.2.1 default came from measuring a
stock prompt at the default retrieval depth — 23,824 characters, about 200 of
margin. On a live BUS101 turn the margin was 46 characters and the assembler was
already cutting:

```
budget 24000 ->  23,467 total   course_content  8,319 [TRUNCATED]   widget_features 0 [DROPPED]
budget 60000 ->  27,991 total   course_content 12,170 (full)        widget_features 1,016
discarded: 3,851 chars of retrieved course material, about 32%
```

Default raised to 36,000. The lesson worth keeping: that measurement was correct
but taken at default `rag_topk`, so the margin looked adequate and was not. A
budget has to clear the high end of retrieval settings, a long topic list and a
per-course system prompt — not the median case.

**Truncation is now visible.** `[TRUNCATED]` and `[DROPPED]` appeared only in the
prompt debug log, which is off by default. That is how a budget too small to hold
the prompt shipped twice. The plugin now records when course content had to be
cut and warns on the settings page, beside the setting you would change.

**Per-quiz assistance levels survive a restore again.** Course-module mappings do
not exist while the course task runs, so every lookup returned false: quiz
assistance levels were dropped on every restore and duplicate — including
`hidden`, used for summative quizzes — and message and flashcard `cmid`s stored
as null. Those rows are now resolved in `after_restore_course()`, which core
dispatches once every activity exists.

**Two of three analytics charts were never drawn.** The server sends hourly and
day-of-week nested under `time_distribution`; the JavaScript read them at the top
level, so both guards were permanently undefined.

**Provider API keys are out of `config_log`.** Every edit of the
comparison-providers field wrote credentials to `mdl_config_log` in clear text.
Only the key is redacted; provider, model and base URL still show.

**The spend floor tells you when it refuses**, in the browser, attached to the
field. **A pause records as `chat_paused`**, not `sse_error`. **The per-message
audit row** — time, course, length, IP, never content — is now in the privacy
notice. **The total-tokens tile** says it counts embedding and reranking calls,
which is why it can read hundreds of millions beside zero sessions.

### Upgrade notes

No schema change. One upgrade step: sites still on the 24,000 default move to
36,000. A tuned value is left alone.

### Testing

999 tests, 4,800 assertions, no failures. 36/36 validators. Full CI matrix green.

## Part 3: Admin Walkthrough

### 1. Ask a course question from a course page

Open a course with retrieval on and an index built, navigate to a page inside it,
and ask something answerable only from the course text.

**Expected:** the answer quotes the course. Grounding renders as a chip beneath
the reply naming the source activity — *From: Forms of Business Ownership* — not
as inline `[[c:N]]` markers. Those markers are the model's internal citation
protocol; the renderer converts them and they should never be visible. If you
see a literal `[[c:N]]` in an answer, that is a bug.

### 2. Check the settings page for a truncation warning

Site administration → AI Course Assistant. If SOLA has recently had to cut
retrieved course content to fit the budget, a warning appears above the system
prompt character budget with the time it last happened. On a healthy site at the
new 36,000 default you should not see it. If you do, raise the budget or lower
`rag_topk`.

### 3. Test the emergency chat switch as a student

Disable chat, then open a course in a private window as a test student. You
should get a short paused notice. Check it as an administrator too — it stops you
as well, which is the point.

Then open the audit log: the pause is recorded as `chat_paused`, not as an error
row.

### 4. Look at the analytics charts

Site administration → Analytics. **All three charts on the overview tab should
draw**: Daily Usage Trend, Hour of Day, and Day of Week. Before this release the
last two were never created and the tab showed one chart and two bare headings.

Note the Total tokens tile counts every AI call including retrieval, so on a site
with RAG enabled it is dominated by embedding and reranking and will look very
large next to the chat session counts. Both are correct; they measure different
things.

### 5. Duplicate a course that uses per-quiz assistance levels

Set a quiz to a restricted assistance level, duplicate the course, and open the
copy's quiz settings. The level should have travelled and should point at the
copy's own quiz. This did not work before this release.
