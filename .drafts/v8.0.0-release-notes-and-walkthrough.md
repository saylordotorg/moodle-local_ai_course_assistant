# SOLA v8.0.0: Release Notes, Feature Summary, and Admin Walkthrough

## Part 1: Release Notes (17 November 2026)

## v8.0.0 (17 November 2026): A rebranded site never says "SOLA"

**Why this release exists.** An institution that renamed the assistant in **Essentials > Branding** still saw "SOLA" in places, most visibly in the tooltip on the floating chat button. Reported on a Moodle 5.3 site. The server rendered the right name, then the widget's own translation step overwrote it with a bundled string that hardcoded "SOLA" in all 46 languages. This release routes every learner-facing, model-facing and admin-facing use of the name through the four branding settings. A site that never changed them looks the same as before. There's no new setting, no schema change and no upgrade step.

**The tooltip and the widget.**

- The open-button label ("Open SOLA") in the bundled translations now carries a brand placeholder in every language, in that language's own word order ("Open {$a}", "{$a}を開く").
- The widget's translation step now fills EVERY `{$a}` with the configured short name and every `[[tutorshort]]`, `[[tutorname]]`, `[[uniname]]` and `[[unishort]]` token from the brand map on the widget root. The help panel uses the same helper, so the two can't drift apart again. Before, it filled only the first `{$a}` and ignored brand tokens.
- Text the widget builds in JavaScript now uses the configured short name: the settings tour, the explanation-style help, the Voice section heading, the rating panel and its thank-you, the usability-test hints and buttons, the talking-avatar frame title, the quiz intro card and the "paused during quizzes" fallback. The saved-responses empty message falls back to the same wording as its language string.

**What the model hears.** Text the model is told can come back to the learner, so it now uses the configured name too: the voice-mode pronunciation coaching ("You are ... in a real-time voice conversation", both in the browser and on the server), the quiz coach-mode block, and the reply-language section, which used to make the model ask learners whether to "switch SOLA" to another language. The scrub that removes a leaked system-prompt identity line from replies no longer depends on the name, so it still catches "You are Atlas (Online Learning Assistant)".

**Emails and admin pages.** These now use the configured names: the learner milestone email's footer reason, the inactivity reminder, the default end-of-course survey title and the default usability test (title and tasks), the cost anomaly, spend guard, unanswered-question, price drift, anomaly digest, integrity report and Learning Radar emails, the health check and backend self-test messages, the analytics assistant prompt and its transcript labels, the insights prompt, the student profile summary, the mobile app view and the version banner on the settings pages.

**Deliberately left alone.** Protocol tags such as `[SOLA_NEXT]`, identifiers and config names, developer debugging and log lines, the `SOLATEST` demo course, user-agent strings, the internal benchmark prompts, the admin-only Learning Radar Redash setup guide (where "SOLA" names the Redash data source you create), and `'SOLA'` used only as a fallback when the widget root carries no name. An existing default survey or usability test keeps the title it was created with; only a newly created default uses the configured name.

**Upgrade notes.** No upgrade step. Purge caches after upgrading so browsers load the new JavaScript. The Turkish label keeps its suffix as `{$a}'yı aç`, which reads naturally for most names; a name that needs a different suffix may want a local language override.

### Testing

- New `tests/branding_hardcoded_test.php` (5 tests) sets the short name to Atlas and checks the rendered floating button (`title` and `aria-label` read "Open Atlas", `data-shortname` carries it), the default survey title and usability tasks, the cost anomaly email's subject and body, the reply-language prompt, and the prompt-leak scrub against "You are Atlas (Online Learning Assistant)". Four of its guards were proven with `scripts/prove_test.py` by putting the old literal back (email subject, reply-language prompt, scrub pattern, survey title): each was caught.
- New `tests/js/branding-literal-check.js`: no language's `open` label contains "SOLA" and each carries `{$a}`; the real `resolveBrandText()` from `chat.js` replaces every `{$a}` and every brand token and keeps word order; `applyI18n` and the help panel both use it; a scan of `amd/src` fails on a new learner-facing "SOLA" string literal (allowlist: fallbacks, protocol tags, console logs, comments, the admin-only Redash guide); and the `amd/build` bundles carry the fix. Run against the 7.12.5 sources it fails 12 of its checks.
- Full plugin PHPUnit suite on MySQL (Moodle 4.5, PHP 8.3): 3242 tests, 105220 assertions, 0 failures, 8 skipped. It ran on the code before the version bump, which is the only change after it. All seven `tests/js` checks pass. ESLint reports no new errors in the five changed JavaScript files.
- Release step, not filled in yet: the CI result on the release commit and the dev and alpha deploy check.

Plugin version `2026111700`, release `8.0.0`.

## Part 2: Key SOLA Features

What the plugin does as of v8.0.0, for an admin deciding what to switch on.

- **A tutor that knows the course.** Answers come from the course itself, with
  optional semantic retrieval over pages, books, PDF, DOCX, PPTX, H5P and SCORM
  content and video transcripts.
- **Practice built in.** Practice quizzes, flashcards, worked examples, study
  plans with reminders, and essay feedback against a rubric. Practice only,
  never a Moodle grade.
- **Steps back during assessment.** While a learner has a quiz attempt open, the
  assistant is unavailable to them everywhere, including outside the course.
- **Support outside courses** (optional). On the dashboard and site pages it
  answers enrolment, certificate and technical questions from a support course
  and the FAQ, with its own three starters, and can hand off to Zendesk.
- **Readable answers.** Headings, lists, tables, quotes and code render in the
  chat, and an answer that runs out of room says so rather than stopping
  silently.
- **46 languages**, with automatic reply-in-your-language, speech input and
  output, and an optional live voice mode. Works on phones, including with
  Moodle's menu drawer open.
- **Any provider, one table of keys.** Gemini, OpenAI, Claude (including Opus
  5.5 and Sonnet 5.5), DeepSeek, Mistral, xAI, MiniMax, OpenRouter, Together,
  Ollama, Moodle's own AI subsystem, or any OpenAI-compatible endpoint. Every
  provider's key, models and base URL live in one **Providers and keys** table,
  so you can add or change a key without touching the default provider.
  Embedding, Rerank and Voice can use a row's key instead of a pasted copy.
  Failover, a premium tier for hard turns (Claude Sonnet 5, benchmark-backed),
  and spend caps per course.
- **Keeps up with new models.** It knows what each model accepts from data
  rather than name checks, fixes a rejected request by itself, and (unless an
  admin turns it off) tests newer models nightly and switches to one that's
  the same price or cheaper and at least as good, rolling back if live answers
  get worse.
- **Costs you can see.** A model registry with prices and their sources, a daily
  price-drift check, token analytics, cost anomaly alerts and benchmarks.
- **Safe defaults.** Nothing contacts a third party until an admin configures
  it: remote configuration, the Python sandbox runtime and the CDN delivery all
  default to off. The assistant opens by itself only on course pages, and only
  if an admin turns auto-open on.
- **Keys encrypted at rest, never shown, and replaced in one step.** Provider
  keys, the Voice providers table, webhook URLs and every other secret are
  stored with Moodle's own encryption, so a database backup alone doesn't
  reveal them. No settings page ever shows a key: a saved one reads "Saved, ends
  in ab12", and the settings-changed notice and Moodle's configuration log hide
  secrets too. A command lists where each key is stored (by its last four
  characters only) and replaces one key everywhere in a single transaction, and
  a Reports > Status check flags a key kept in several places.
- **White-label.** Four settings in Essentials > Branding rename the whole
  product, in every language: the widget and its tooltips, the prompts the
  model sees, alert and learner emails, default surveys and admin pages.
- **Instructor views.** Analytics, a review queue for learner feedback, Learning
  Radar, transcripts with pseudonyms, and surveys with validated rating scales.
- **Python sandbox** (per course). Runs in the learner's browser, never on the
  server, and shows the full error when code fails.
- **PresenterAI replaces Soapbox.** Soapbox has been hidden and switched off
  since 7.12.5; its data, playback and privacy handling stay until PresenterAI
  has imported it.

## Part 3: Admin Walkthrough Script: renaming the assistant (about 6 minutes, conversational)

This is written to be read aloud while you click. It assumes a test site that has just upgraded to 8.0.0 (the dev fleet is the place for it), an admin login, a course with the assistant switched on, and a student account. Change the names back at the end if the site is shared.

### 1. Purge caches (about 30 seconds)

"First thing after any upgrade: purge caches." Do that under **Site administration, Development, Purge caches**. "This release is mostly JavaScript, so a browser holding the old bundle would still show the old name. Purging fixes that."

### 2. Rename the assistant (about 1 minute)

Open **Site administration, Plugins, Local plugins, AI Course Assistant, Essentials** and find the **Branding** section. Set the short name to `Atlas` and the display name to `Atlas Learning Assistant`. Save.

"These four settings, the two product names and the two institution names, are the whole brand. Nothing else needs editing: not a language file, not a template."

### 3. The tooltip (about 1 minute)

Open the course as the student. Hover over the floating chat button.

"It says **Open Atlas**. Before this release it said Open SOLA here, even though the server had written Open Atlas, because the widget rewrote it from its own translation table." Open the settings panel in the widget, switch the language to Spanish, close the panel and hover again. "**Abrir Atlas**. Every language keeps its own word order. In Japanese it's Atlasを開く, with the name first."

### 4. Inside the widget (about 1 minute)

Open the settings panel. "The tour card says how Atlas explains things, the explanation-style help names Atlas, and if voice is on, the section is **Atlas Voice**." If feedback is on, open it. "The rating question asks how you'd rate Atlas." Start a practice quiz setup. "The intro card says Atlas will generate a fresh quiz."

### 5. What the model says (about 1 minute)

Switch the widget language to French, then type a full question in English.

"The assistant asks before switching languages, and it asks whether you'd like to switch Atlas to English. It used to say SOLA here, because that's what its instructions told it." If voice mode is on, start Pronunciation Practice. "The voice coach introduces itself as Atlas too."

### 6. Emails and admin pages (about 1 minute)

"The alert emails are named for the assistant now." If you have a test inbox in **Spend notification emails**, run the alert self-test from a shell:

```bash
sudo -u www-data php local/ai_course_assistant/admin/cli/send_spend_alert_test_email.php
```

"That self-test script is a developer tool and still says SOLA. The real alerts, cost anomaly, spend guard, unanswered questions and price drift, put the configured name in the subject." Then open **Site administration, Reports, Status** and the backend self-test page. "The health messages name Atlas too."

### 7. Put it back (about 30 seconds)

If the site is shared, set the short name back to `SOLA` and the display name back to `Saylor Online Learning Assistant`, save, and purge caches. "Everything goes back exactly as it was. The defaults never changed."
