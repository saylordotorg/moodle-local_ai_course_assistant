# SOLA v7.5.0 — Release Notes, Feature Summary, and 20-minute Admin Walkthrough

## Part 1: Release Notes (17 September 2026)

**A course can now answer from another course, and three things a learner actually sees — ids in the prose, English chip labels in a Spanish drawer, and missing source links — stop being wrong.**

- **A learner asking "how do exams work?" can be answered from the orientation course.** Retrieval was scoped to one course plus the site FAQ. On Degrees the Student Resource Center is indexed and visible and was still unreachable from anywhere else, so that question got nothing. `supplemental_courses` (site-wide, with a per-course override) names courses whose already-indexed chunks retrieval may also score. Nothing extra is embedded, so pointing ninety courses at one orientation course costs nothing and stays in step when that course is reindexed.
  - A per-course value **replaces** the site list rather than adding to it, so "this course must not see the orientation material" is expressible. Hidden courses are dropped — retrieval is not a route around course visibility, and Learn's obvious orientation candidate is hidden today. Capped at five, because every listed course is loaded and scored on every retrieval. Ids are per site: the same course is 16 on Degrees and 506 on Learn.
- **Course-module ids stop reaching learners as prose.** Replies read "Watch the Unit 1 Introduction Video (id:20057)". The system prompt has forbidden this since v7.0 and 12.2% of Learn replies (2,112/17,265) and 8.0% of Degrees replies (151/1,878) did it anyway. A prompt rule is a request; this is the enforcement, applied to the live stream and to the copy the teacher-facing transcript CSV reads. A `[SOURCE:activity:20057]` marker keeps its id, which is the one place an id belongs.
- **Starter chips and source pills follow the language.** Every built-in starter's name and help text was a literal English string in `starter_manager::get_defaults()`, so a learner on a Spanish site read Spanish everywhere in the drawer except the chips. The source pill read "From: Course Materials" in all 46 languages. 25 new keys translated into all 45 non-English locales — roughly 1,100 strings.
- **Source links come back on RAG courses.** Measured on 24 paired prompts: **75%** of replies carried a `[SOURCE:]` tag with no retrieved chunks in context, **13%** with them (Fisher exact, p = 2.6 × 10⁻⁵). Retrieval was suppressing attribution, and every Degrees course runs with retrieval on. A second measurement decided the shape of the fix: tapping the live stream on a Degrees course page, retrieval returned three chunks and the reply carried **neither** `[SOURCE:]` nor a single `[[c:N]]`. The model is not choosing one marker over the other, it is skipping attribution altogether once retrieved content is present. So the prompt now states that the two markers are complementary rather than alternatives, and the browser falls back to a **course-level** pill whenever retrieval fed the answer and the model named nothing. A cited `[[c:N]]` still resolves to that exact activity; the specific-page link stays something the model earns by citing, because naming a page the model may not have used would read as precision the data does not support.

### Known gaps, recorded deliberately

- **The prompt half of the source-attribution fix is not independently measured yet.** The stream tap shows the model currently emits no marker of either kind on Degrees, so the wording change is doing real work and the browser fallback is only a course-level pill behind it. The wording has not been re-run through the 24×2 harness on a build that contains it; that measurement is the first thing to do after this deploys to dev.
- **A course-level pill is all the fallback can honestly claim.** It restores a visible, working source link on every retrieval answer, which was the reported symptom, but it does not name the page. The specific-activity link comes back only as the model starts citing again.
- **A supplemental course dilutes the course's own material.** Every listed course's chunks compete in the same cosine ranking. The cap of five bounds it; there is no per-source weighting.
- **`KNOWN_UNTRANSLATED` holds 383 admin-only diagnostic keys.** Unchanged this release, and now documented accurately — `Internationalization.md` had claimed the list was empty since v6.9.5.

### Testing

- Full PHPUnit suite: see the run recorded at release time; gate is 0 failures.
- 12 new tests cover the id scrub, including the shapes observed in production, the innocent parentheticals that must survive, idempotence (it runs on both the stream chunk and the stored copy), and that a `[SOURCE:]` marker keeps its id.
- 10 tests cover supplemental scoping, including that an orientation course's chunks become scoreable from another course and that a hidden one contributes nothing.
- Translation parity: every `lang/en` key present in all 45 non-English locales, except the 383 deliberately staged.
- PHP lint clean on every modified file; `node --check` clean on every modified AMD source.
- Jailbreak suite: see the run recorded at release time. Gate is 0 FAIL and 0 ERROR, not a pass rate.

## Part 2: Key SOLA Features

Carried forward from v7.2.3. One new feature this release: **supplemental
courses** (`supplemental_courses` site-wide plus a per-course override on the
course settings page), which lets retrieval draw on another course's indexed
content. Admin settings added since 7.2.3: System prompt budget mode (7.2.4),
quiz-lock scope (7.2.5), a settings-page warning when auto budget mode has no
context window to derive from (7.2.7), and supplemental courses (7.5.0). One
admin CLI added, `audit_config_log_secrets.php` (7.2.4). The budget auto-tuner is
deprecated as of 7.2.6 and stands down unless the budget mode is `fixed`.

## Part 3: Admin Walkthrough

### 1. Point a course at your orientation course

Site administration → AI Course Assistant → **Supplemental courses**. Enter the
id of your student orientation or resource centre. Then open a course that has
nothing to say about exam policy and ask "how do exams work?".

**Expected:** an answer drawn from the orientation course, with a source pill
that links **into that course**, not back to the one you are sitting in. Before
this release the same question returned a general non-answer.

Check the id on the site you are configuring. Learn and Degrees are separate
Moodle instances, so the same orientation course has a different id on each.

### 2. Confirm a hidden course contributes nothing

Hide the course you just listed, purge caches, ask the same question again.

**Expected:** back to the general non-answer. This is deliberate: retrieval must
not become a way around course visibility. Learn's own orientation candidate is
hidden today, so this is the live case, not a hypothetical one.

### 3. Confirm a per-course value replaces rather than adds

With a site-wide list set, open a course's SOLA settings and enter a different
single id.

**Expected:** the help text names the site-wide list and tells you a value here
replaces it. That is the point — it has to be possible to say "this course must
not see the orientation material", and opting one course out is the likelier
need than adding one more.

### 4. Ask for a study plan and read the prose

Ask "build me a study plan for this course" in a course with several activities.

**Expected:** activities referred to by name. No "(id:20057)", no "(Activity ID:
89206)". Before this release that question produced an id in the prose nearly
every time, because a study plan enumerates activities and the structure block
annotates each one with its id.

### 5. Switch language inside the drawer

Open the drawer, use the globe icon, pick Spanish.

**Expected:** the chip labels change, **and so does the hover help text on each
chip**, and so does the source pill under the last answer. Before this release
the labels changed and nothing else did.

If mastery tracking is on and the "What should I focus on?" chip is showing a
named objective, that chip keeps its personalized label rather than reverting to
a generic translation.

### 6. Check a source pill on a retrieval course

In a course with RAG enabled, ask a content question.

**Expected:** a pill under the answer, and it is a link. Before this release the
pill was usually absent on exactly the courses where retrieval was working.

### 7. Reindex a supplemental course and ask again

Reindex the orientation course from `rag_admin.php`, then ask the question from
step 1 again from a different course.

**Expected:** the answer reflects the new content immediately. The supplemental
list is part of the packed-index cache key, so a scope change does not wait for
the generation counter to bump.
