# SOLA v6.9.5 — Release Notes, Feature Summary, and 20-minute Admin Walkthrough

## Part 1: Release Notes (5 August 2026)

Retrieval got faster and more selective, and cost reporting started telling the truth about what retrieval costs.

Ships everything merged since v6.9.4: PRs #171 through #176 plus the cost-reporting and export work.

### Read this before upgrading

**If you consume the Redash export, three changes will alter what an existing data source pulls.** The version number is a patch bump and does not signal this, so it is spelled out here.

- **`since` absent now means the last 90 days, not all time.** A data source that never passed `since` was pulling every row ever recorded and will now pull a 90-day window. Pass `since=0` explicitly to keep the old behaviour, or set the new "Export lookback window (days)" to 0.
- **`anonymize=0` now returns HTTP 403** unless an admin enables the new "Allow de-anonymized export" setting. Any consumer relying on de-anonymized output breaks until that is turned on.
- **Learner identity fields changed shape.** `student_usage` no longer emits `userid` or `name` when anonymized; it emits `user_ref`, matching `feedback`. `survey_responses` non-anonymized rows now use `userid` rather than putting a raw id under `user_ref`. `user_ref` now always means pseudonym and `userid` always means a real id.
- Additive, not breaking: `token_costs` gains a `category` column (`chat` / `embedding` / `rerank`), the response gains `sections` and `since`, and a new `sections` parameter lets a caller ask for only the sections it needs. Absent still returns everything.

**Reported numbers move, in both directions.**

- **Tokens (30d) and per-model spend rise** on any site with RAG enabled, because they now include embedding and rerank cost. The gap between the site-wide total and the sum of per-course totals is the RAG bill, since indexing is booked against the site course rather than a course.
- **Course message counts fall.** `total_messages` had been counting `role='system'` telemetry as learner messages. The site course was the loud case, reporting tens of thousands of "messages" that were RAG indexing ledger entries.

**A new database column, no forced reindex.** #172 adds `embedding_bin` alongside the existing JSON `embedding` column. The JSON column is retained and still written, retrieval falls back to JSON per row, and the backfill is a separate resumable CLI (`admin/cli/backfill_embedding_bin.php`, with `--dry-run` and `--verify`) rather than an upgrade-time loop. So the upgrade is safe on a large catalogue, a partially backfilled index works, and the release rolls back without a reindex. Run the backfill when convenient to get the speed-up.

### Retrieval (#170, #171, #172, #173)

- **Reranking is now gated on ambiguity** (#171). It runs only when the cosine margin between the top-1 and top-3 candidates falls below `rerank_margin_threshold` (default 0.086), which skips roughly 30% of queries with no measurable recall loss, and avoids the cases where reranking displaced an already-correct top result. Measured over all 1,008 fixtures through the real retrieval path on dev.
- **The rerank candidate pool default drops 50 to 20** (#174). Measured over the same 1,008 queries: 20 matches 30 on recall (R@3 89.0% versus 89.3%) for a third less cost, while 50 costs 2.5 times as much with no measurable gain. Below 10 recall degrades.
- **The retrieval load phase is roughly twice as fast** (#172). `json_decode` was 40 to 46% of every cold `retrieve()` call; vectors now also store packed as float32 in `embedding_bin`, which retrieval prefers. Verified by re-decoding all 10,897 dev chunks against their JSON originals with zero mismatches and a maximum cosine delta of 0.0, so ranking and every measured baseline are unaffected.
- **A stale-vector cache bug is fixed** (#173). `rag_retriever` held decoded vectors in a method-local static that nothing ever invalidated, so a reindex mid-process left every subsequent retrieval scoring the old index. Harmless for a single web request, materially wrong for the reindex CLI, the benchmark harnesses and scheduled tasks, any of which could silently measure or serve pre-reindex vectors. `hydrate_content()` also now drops rows whose chunk vanished between scoring and hydration rather than passing an empty passage into the prompt.

### Cost reporting

- **Voyage AI embedding and reranker rates added to the rate card**, from the Voyage pricing page on 4 August 2026, so RAG spend reports a dollar figure instead of "unknown". The plugin defaults, voyage-3.5 and rerank-2.5, are both covered. Rates were looked up rather than recalled: a wrong rate is worse than the null it replaces, because null reads as unknown while a wrong number reads as authoritative.
- **Five surfaces counted chat spend only and now count all billable rows.** The embedding and rerank cost ledger is written with `role='system'`, and every place that summed spend had its own inline `role='assistant'` filter. Fixed in the Redash export's `token_costs`, the Learning Radar "Tokens (30d)" chip, `llm_optimizer`, the token analytics per-model table, and the cost-anomaly detector plus its digest. The predicate now has one definition rather than six.
- **A runaway reindex can now trigger the cost-anomaly alert**, which previously could not see the one category of runaway it exists to catch.
- **The RAG spend cap enforces**, where it previously only displayed. Exceeding it stops query embedding and reranking, so retrieval degrades to no context and chat keeps answering without citations, and stops indexing. A cap-stopped indexing run deliberately does not prune the existing index. Inert unless a cap is configured, which is every existing site.
- **The `rag` spend capability could never match a row**, because its base clause required `role='assistant'` while the capability required an embedding interaction type. The RAG line in the admin spend panel therefore read $0.00 at any indexing volume. Reranker spend also belonged to no capability at all, and now belongs to this one.
- **The RAG benchmark harness prices reranking through the rate card** instead of a hardcoded rate. Output is identical for rerank-2.5, so previously published benchmark figures still stand.
- **Course message counts exclude telemetry**, and the export's course list no longer invents a phantom course out of indexing telemetry, and honours `since` like the metrics inside it do.

### Security and privacy

- **`redash_api_key` is masked in `config_log`** (#174). It was a plain configtext, so every historical value was recoverable in the clear from a table that is never purged; found on production while diagnosing an unrelated problem. A standing test now asserts that credential settings are password types.
- **`soapbox_storage_key` had the same defect** and is now a password type too. It is an IAM access key ID whose sibling `soapbox_storage_secret` was already correct. It also slipped past the new guard, whose hint list matched `apikey` and `api_key` but not a bare `key`; the hint list was widened.
- **Two learner-identity leaks in the export are closed.** `student_usage` emitted the real `userid` next to the pseudonym under `anonymize=1`, which defeats the pseudonym, and `learning_radar_queries` emitted a raw `userid` unconditionally.
- **`amd/build/sse_client.min.js` rebuilt.** It predated its source by two months, which meant the v5.5.4 SSE accumulator caps, a red-team finding recorded as fixed in the changelog, had never actually shipped to any site. The 1 MB buffer and 256 KB per-line ceilings are now in the served bundle.

### Packaging and i18n (#175, #176)

- **A tracked `.pyc` was going into the plugin zip** (#175). `__pycache__/` and `*.py[cod]` are now ignored, the stray artifact is untracked, and the zip excludes it. **`scripts/` is now excluded from the zip too** (#176), matching how `deploy_dev.py` and `create_fixed_zip.sh` are already treated: it is release tooling with no runtime role.
- **i18n parity restored.** Eight English strings had no translation in any locale; they are now translated into all 45 non-English locales. The stale `rerank_candidates_desc` translations that still told admins the default was 50 were corrected to 20 in all 45. `lang_completeness_test` now fails if a new English-only string is added, which is how the original gap went unnoticed.

### Testing

- Full suite 767 pass, 1 skipped. Validator suite 36 of 36.
- **Jailbreak suite, 6 August 2026.** 32 cases across 12 categories, live against the real system prompt.
  - **openai / gpt-4o-mini: 32 pass, 0 fail, 0 review.** Identical to the figure recorded for v6.9.4, so no regression.
  - **gemini-2.5-flash, the production primary: 0 fail** across two runs, scoring 27 pass / 5 review and then 24 pass / 8 review.
  - Every REVIEW case was read in full and is a refusal the pass-indicator regexes did not recognise, not a leak. The two cross-learner prompts drew explicit denials of holding other learners' data plus a redirect to the analytics dashboard; the indirect-injection prompt drew "I can't ignore my core instructions", which is the v6.9.4 rule working.
  - For future runs: the pass/review split is not stable between runs on the same model and settings, because REVIEW only means "no pass-indicator matched". FAIL is the signal, and it was 0 in every run. Reporting a single pass-rate percentage from one run overstates the precision of this harness.
- Each fix was verified against its own regression by reverting the fix and confirming the intended tests fail, including two guards that must pass either way: chat spend is still counted, and premium-router telemetry is still excluded from spend.
- PHP lint clean on every modified file; `node --check` clean on the rebuilt bundle.

## Part 3: Admin Walkthrough

Core drawer, quiz, voice, analytics, privacy, Soapbox, and WSCUC-outcomes flows are carried forward from v6.8.32 / v6.8.20 / v6.8.5. Concrete steps for the new v6.9.x surfaces are below.

### Choosing a provider mode (v6.9.3)

1. **Open plugin settings.** Site administration, Plugins, Local plugins, SOLA. Find the chat Provider setting near the top.
2. **Explain Auto.** The default is now Auto. Talking point: "Auto means SOLA uses your plugin-configured API key if you set one; if you leave the key blank and your Moodle site has the built-in AI subsystem configured, SOLA uses that instead. Nothing to change for an existing install with a key."
3. **Show the resolution.** On the backend self-test page, the core AI probe reports whether the Moodle AI subsystem is present and what Auto currently resolves to on this site.
4. **Name the two audiences.** Sites that centralize LLM credentials in Moodle can leave the SOLA key blank and let Auto route through the subsystem; sites that manage keys per plugin keep doing exactly what they did before.

### Turning on parent-document retrieval (v6.9.2)

Prerequisite: RAG is enabled and a course is indexed.

1. **Find the retrieval settings.** In plugin settings, the RAG group now has Return scope, Window size, and Parent max chars.
2. **Pick a scope.** Default is chunk (send only the matched chunk). Window sends the matched chunk plus its neighbors; page sends the whole source page (size-capped by Parent max chars). Talking point: "Window and page give the model more surrounding context, which helps on longer, conversational questions; chunk is leanest on tokens."
3. **Tune fleet-wide if wanted.** These three keys are on the policy-bundle allowlist, so a multi-site operator can set them once in the signed bundle rather than per site.

### The hardening (v6.9.4), for context

No admin action required. The two new security rules are always on and cannot be overridden by a custom system-prompt persona. Talking point for a security review: "The tutor will not accept a role a user merely claims in chat, and it treats 'ignore your instructions and do X' as an injection even when X looks harmless."

### Reading the RAG bill and setting a cap (v6.9.5)

1. **Open token analytics.** Site administration, Plugins, Local plugins, SOLA, then the Token analytics quicklink. Talking point: "The category card splits spend into Chat, Voice, RAG and Analytics. Before this release the RAG row was always empty, because the query behind it could not match an embedding row."
2. **Point at the RAG row.** It should now carry a dollar figure on any site with RAG enabled. If it reads "n/a" rather than a number, the embedding model is not in the rate card; the Voyage and OpenAI models are.
3. **Explain the reconciliation.** The site-wide Tokens (30d) figure is larger than the sum of the per-course figures, and that is deliberate: indexing is booked against the site course, not the course whose content was indexed. The difference is the RAG bill.
4. **Set a RAG cap.** In plugin settings find the spend cap fields. Enter a monthly figure for RAG. Talking point: "Until this release this number was decoration. It now stops query embedding, reranking and indexing when the period's spend passes it."
5. **Explain the failure mode, which is the important part.** When the cap is hit, chat keeps working; it just answers without retrieved course context or citations. Indexing stops and, critically, does not prune the existing index, so a cap-stopped run cannot leave you with a half-deleted index.
6. **Leave it blank to opt out.** An empty or zero cap means unlimited, which is what every existing site has, so nothing changes for them.

### The export settings (v6.9.5)

1. **Find the Analytics Export section** in plugin settings.
2. **Export lookback window (days).** Default 90. Talking point: "If your Redash data source does not pass a `since` timestamp, this is how far back it reaches. It used to reach back forever." Set 0 to restore the old all-time default.
3. **Allow de-anonymized export.** Leave off. Talking point: "The export authenticates with a shared API key, not a signed-in administrator, so anyone holding that key could previously ask for real learner names. Now that has to be deliberately enabled here first."
4. **Mention `sections`.** Point out that a data source can pass `sections=courses,feedback,token_costs` so the payload stops carrying raw transcript excerpts it never needed.
