# SOLA v6.9.5 — Release Notes, Feature Summary, and 20-minute Admin Walkthrough

## Part 1: Release Notes (5 August 2026)

Cost reporting now tells the truth about RAG: every surface that reports token spend counts the embedding and rerank spend it used to omit, the Voyage rate card makes that spend priceable, and the RAG budget cap it feeds actually enforces.

### Read this before upgrading if you consume the Redash export

The export changes in ways that will alter what an existing data source pulls. The version number does not signal this, so it is spelled out here.

- **`since` absent now means the last 90 days, not all time.** A data source that never passed `since` was pulling every row ever recorded and will now pull a 90-day window. Pass `since=0` explicitly to keep the old behaviour, or set the new "Export lookback window (days)" to 0.
- **`anonymize=0` now returns HTTP 403** unless an admin enables the new "Allow de-anonymized export" setting. Any consumer relying on de-anonymized output will break until that is turned on.
- **Learner identity fields changed.** `student_usage` no longer emits `userid` or `name` when anonymized; it emits `user_ref`, matching `feedback`. `survey_responses` non-anonymized rows now use `userid` rather than putting a raw id under `user_ref`. `user_ref` now always means pseudonym and `userid` always means a real id.
- **`token_costs` gains a `category` column** (`chat` / `embedding` / `rerank`) and the response gains `sections` and `since`.
- **New `sections` parameter.** Absent still returns everything; naming the sections you need keeps the raw transcript excerpt and Learning Radar bodies out of the payload.

### Reported numbers move, in both directions

- **Tokens (30d) and per-model spend go up** on any site with RAG enabled, because they now include embedding and rerank cost. The gap between that total and the sum of per-course totals is your RAG bill, since indexing is booked against the site course rather than a course.
- **Course message counts go down.** `total_messages` counted `role='system'` telemetry as learner messages. The site course was the loud case, reporting tens of thousands of "messages" that were RAG indexing ledger entries.

### Changes

- Voyage AI embedding and reranker rates added to the rate card, so RAG spend reports a dollar figure instead of "unknown". Rates from the Voyage pricing page, 4 August 2026. The plugin defaults, voyage-3.5 and rerank-2.5, are both covered.
- The RAG spend cap is enforced, not just displayed. Exceeding it stops query embedding and reranking (retrieval degrades to no context, so chat keeps working without citations) and stops indexing. A cap-stopped indexing run explicitly does not prune the existing index. Inert unless a cap is configured.
- The `rag` spend capability could never match a row, so the RAG line in the admin spend panel always read $0.00 regardless of indexing volume. Fixed, and reranker spend now belongs to that capability instead of no capability at all.
- The cost-anomaly detector and the anomaly digest count RAG spend, so a runaway reindex can trigger the alert that exists to catch runaways.
- `soapbox_storage_key` is an IAM access key ID that was stored as plain text in `mdl_config_log`; it is now a password-type setting. The guard that checks for this class of mistake was widened so a setting named `..._key` cannot slip past it again.
- The token analytics per-model table and missing-data audit now count the same population as the category card above them, so the figures on that page reconcile.
- The RAG benchmark harness prices reranking through the rate card instead of a hardcoded rate. Output is unchanged for rerank-2.5, so previously published benchmark figures still stand.
- The export's course list no longer invents a phantom course out of indexing telemetry, and it honours `since` like the metrics inside it do.
- `amd/build/sse_client.min.js` rebuilt. It predated its source by two months, which meant the v5.5.4 SSE accumulator caps (a red-team finding recorded as fixed) had never actually shipped to any site.
- i18n: the eight English strings that had no translations are now translated into all 45 non-English locales, and the stale `rerank_candidates_desc` translations that still said "default 50" were corrected to 20. `lang_completeness_test` now fails if a new English-only string is added, which is how the previous gap went unnoticed.

## Part 3: Admin Walkthrough

Core drawer, quiz, voice, analytics, privacy, Soapbox, and WSCUC-outcomes flows are carried forward from v6.8.32 / v6.8.20 / v6.8.5. Concrete steps for the new v6.9.x surfaces are below.

### Choosing a provider mode (v6.9.3)

1. **Open plugin settings.** Site administration, Plugins, Local plugins, SOLA. Find the chat Provider setting near the top.
2. **Explain Auto.** The default is now Auto. Talking point: "Auto means SOLA uses your plugin-configured API key if you set one; if you leave the key blank and your Moodle site has the built-in AI subsystem configured, SOLA uses that instead. Nothing to change for an existing install with a key."
3. **Show the resolution.** On the backend self-test page, the core AI probe reports whether the Moodle AI subsystem is present and what Auto currently resolves to on this site.
4. **Name the two audiences.** Sites that centralize LLM credentials in Moodle can leave the SOLA key blank and let Auto route through the subsystem; sites that manage keys per plugin keep doing exactly what they did before.

### Turning on parent-document retrieval (v6.9.2)

Prerequisite: RAG is enabled and a course is indexed.

1. **Find the retrieval settings.** In plugin settings, the RAG group now has Return scope, Window size, and Parent max chars.
2. **Pick a scope.** Default is chunk (send only the matched chunk). Window sends the matched chunk plus its neighbors; page sends the whole source page (size-capped by Parent max chars). Talking point: "Window and page give the model more surrounding context, which helps on longer, conversational questions; chunk is leanest on tokens."
3. **Tune fleet-wide if wanted.** These three keys are on the policy-bundle allowlist, so a multi-site operator can set them once in the signed bundle rather than per site.

### The hardening (v6.9.4), for context

No admin action required. The two new security rules are always on and cannot be overridden by a custom system-prompt persona. Talking point for a security review: "The tutor will not accept a role a user merely claims in chat, and it treats 'ignore your instructions and do X' as an injection even when X looks harmless."

### Reading the RAG bill and setting a cap (v6.9.5)

1. **Open token analytics.** Site administration, Plugins, Local plugins, SOLA, then the Token analytics quicklink. Talking point: "The category card splits spend into Chat, Voice, RAG and Analytics. Before this release the RAG row was always empty, because the query behind it could not match an embedding row."
2. **Point at the RAG row.** It should now carry a dollar figure on any site with RAG enabled. If it reads "n/a" rather than a number, the embedding model is not in the rate card; the Voyage and OpenAI models are.
3. **Explain the reconciliation.** The site-wide Tokens (30d) figure is larger than the sum of the per-course figures, and that is deliberate: indexing is booked against the site course, not the course whose content was indexed. The difference is the RAG bill.
4. **Set a RAG cap.** In plugin settings find the spend cap fields. Enter a monthly figure for RAG. Talking point: "Until this release this number was decoration. It now stops query embedding, reranking and indexing when the period's spend passes it."
5. **Explain the failure mode, which is the important part.** When the cap is hit, chat keeps working; it just answers without retrieved course context or citations. Indexing stops and, critically, does not prune the existing index, so a cap-stopped run cannot leave you with a half-deleted index.
6. **Leave it blank to opt out.** An empty or zero cap means unlimited, which is what every existing site has, so nothing changes for them.

### The export settings (v6.9.5)

1. **Find the Analytics Export section** in plugin settings.
2. **Export lookback window (days).** Default 90. Talking point: "If your Redash data source does not pass a `since` timestamp, this is how far back it reaches. It used to reach back forever." Set 0 to restore the old all-time default.
3. **Allow de-anonymized export.** Leave off. Talking point: "The export authenticates with a shared API key, not a signed-in administrator, so anyone holding that key could previously ask for real learner names. Now that has to be deliberately enabled here first."
4. **Mention `sections`.** Point out that a data source can pass `sections=courses,feedback,token_costs` so the payload stops carrying raw transcript excerpts it never needed.
